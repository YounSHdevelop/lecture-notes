QUEUE

큐(Queue) — 기본 개념과 ADT

큐(Queue)란?

정의

FIFO (First In, First Out) — 선입선출
먼저 삽입된 데이터가 먼저 삭제되는 자료구조.
줄 서기, 프린터 인쇄 대기열이 대표적인 예시.

스택 vs 큐

  • 스택(Stack): 나중에 넣은 것이 먼저 나옴 (LIFO)
  • 큐(Queue): 먼저 넣은 것이 먼저 나옴 (FIFO)
  • 삽입 위치: 큐는 맨 뒤(rear)
  • 삭제 위치: 큐는 맨 앞(front)

큐의 포인터 — front와 rear

front (프런트)

큐의 맨 앞 요소를 가리키는 인덱스.
삭제(dequeue)가 일어나는 위치.
초기값: -1

rear (리어)

큐의 맨 뒤 요소를 가리키는 인덱스.
삽입(enqueue)이 일어나는 위치.
초기값: -1

큐 삽입/삭제 시각화 (MAX=5, 10·20·30 삽입 후)

비어있음 ↑front(-1)
10[0]
20[1]
30 ↑rear(2)
빈칸[3]
빈칸[4]
■ front: 삭제 방향 → ■ rear: 삽입 위치

큐의 ADT (추상 데이터 타입)

코딩 전에 먼저 추상 데이터 타입으로 기능과 인터페이스를 정의하는 것이 중요.

// Queue ADT — 연산 목록 (함수 원형) void create(QueueType *q); // 빈 큐 초기화 void enqueue(QueueType *q, element e); // 맨 뒤에 삽입 element dequeue(QueueType *q); // 맨 앞에서 삭제 후 반환 int isEmpty(QueueType *q); // 비어있으면 1 반환 int isFull(QueueType *q); // 가득 찼으면 1 반환

선형 큐 구현 (배열 이용)

isEmpty 조건

front == rear
초기 상태가 front=rear=-1이므로, 둘이 같으면 비어있음.

isFull 조건

rear == MAX_SIZE - 1
rear가 배열의 마지막 인덱스에 도달하면 가득 참.

enqueue (인큐)

① isFull 확인
② rear++
③ Q[rear] = e

dequeue (디큐)

① isEmpty 확인
② front++
③ return Q[front]
※ 실제로 데이터를 지우는 게 아니라 front 포인터만 이동

// 선형 큐 구조체 및 구현 #define MAX_QUEUE_SIZE 100 typedef int element; typedef struct { element data[MAX_QUEUE_SIZE]; int front; // 삭제 위치 (초기값: -1) int rear; // 삽입 위치 (초기값: -1) } QueueType; void init_queue(QueueType *q) { q->front = -1; q->rear = -1; } void enqueue(QueueType *q, element e) { // rear를 먼저 증가시킨 후 데이터 저장 q->data[++(q->rear)] = e; } element dequeue(QueueType *q) { // front를 먼저 증가시킨 후 데이터 반환 return q->data[++(q->front)]; }
⚠️ 선형 큐의 한계 — 공간 낭비 문제

dequeue를 반복하면 front가 오른쪽으로 이동하여 왼쪽 공간이 낭비된다.
rear가 MAX-1에 도달하면 앞에 빈 공간이 남아있어도 isFull이 되어버리는 문제 발생.
→ 해결책: 원형 큐(Circular Queue)

CIRCULAR QUEUE

원형 큐 (Circular Queue)

원형 큐란?

배열의 끝을 원형으로 이어붙인 구조. 나머지 연산자 %를 사용해 인덱스를 순환시킨다.

핵심 아이디어

(index + 1) % MAX_SIZE
rear나 front가 배열 끝에 도달하면 자동으로 0으로 돌아감.
선형 큐처럼 빈 공간이 낭비되지 않음.

공간 1칸 희생 이유

isEmpty와 isFull 판별을 위해 배열 칸 1개를 사용하지 않음.
isEmpty: front == rear
isFull: (rear+1) % MAX == front

enqueue (원형)

① rear = (rear+1) % MAX
② Q[rear] = e

dequeue (원형)

① front = (front+1) % MAX
② return Q[front]

void enqueue(QueueType *q, element e) { // % 연산으로 인덱스를 0으로 순환시킴 q->rear = (q->rear + 1) % MAX_QUEUE_SIZE; q->data[q->rear] = e; } element dequeue(QueueType *q) { q->front = (q->front + 1) % MAX_QUEUE_SIZE; return q->data[q->front]; } int is_empty(QueueType *q) { return q->front == q->rear; } int is_full(QueueType *q) { // front 바로 앞이 rear면 가득 찬 것 return (q->rear + 1) % MAX_QUEUE_SIZE == q->front; }
📌 선형 큐 vs 원형 큐 비교
항목선형 큐원형 큐
isFull 조건 rear == MAX-1 (rear+1)%MAX == front
인덱스 증가 rear++ rear = (rear+1) % MAX
공간 효율 삭제 후 공간 낭비 공간 재활용 가능
구현 복잡도 단순 약간 복잡 (% 연산)
DEQUE

덱 (Deque — Double-ended Queue)

양쪽 끝(front, rear) 어디서든 삽입과 삭제가 가능한 큐의 변형.

add_front

앞쪽에 데이터 삽입.
front = (front-1+MAX) % MAX
Q[front] = e

add_rear

뒤쪽에 데이터 삽입.
일반 enqueue와 동일.
rear = (rear+1) % MAX

delete_front

앞쪽에서 삭제.
일반 dequeue와 동일.
front = (front+1) % MAX

delete_rear

뒤쪽에서 삭제.
rear = (rear-1+MAX) % MAX
※ 반시계 방향으로 1 감소

✅ 덱과 스택/큐의 관계
  • 덱에서 front에서만 삽입·삭제 → 스택(Stack)처럼 동작
  • 덱에서 rear에 삽입, front에서 삭제 → 일반 큐처럼 동작
  • 원형 큐 코드를 활용해 구현 가능
APPLICATION

큐의 응용 — 시뮬레이션 (은행 대기열)

큐는 순서대로 처리해야 하는 상황에 적합. 은행 창구 대기 시뮬레이션이 대표적인 예.

시뮬레이션 목적

고객이 평균적으로 얼마나 기다리는지 계산.
입력 변수(도착 확률, 서비스 시간)를 바꿔가며 여러 번 실행.

랜덤 변수 활용

고객 도착 확률: 50% (1분에 한 명)
서비스 타임: 난수로 결정
서비스 타임 > 0 → 현재 고객 서비스 중
서비스 타임 = 0 → 다음 고객 대기

시뮬레이션 흐름

1
고객 도착: 매 분 확률(50%)로 고객이 큐에 enqueue
2
서비스 진행: 현재 서비스 타임 > 0이면 감소시키며 처리 계속
3
서비스 완료: 서비스 타임 = 0이 되면 큐 앞에서 dequeue하여 다음 고객 처리 시작
4
대기 시간 누적: 각 고객의 도착 시각과 서비스 시작 시각 차이로 대기 시간 계산
5
평균 계산: 전체 대기 시간 / 고객 수 → 평균 대기 시간 출력
📌 시뮬레이션 핵심
  • duration(시뮬레이션 시간)이 다를 때마다 결과가 달라짐
  • 랜덤 변수이므로 실행할 때마다 다른 결과 → 여러 번 실행하여 평균값 사용
  • 현실에서 큰 영향(은행 직원 수 결정 등)을 미치므로 신중하게 적용
LIST

리스트 (List) — 기본 개념과 배열 구현

리스트란?

정의

순서 있는 데이터의 모임.
삽입과 삭제가 어느 위치든 가능한 것이 리스트의 특징.
스택, 큐는 리스트의 특수한 형태 (삽입/삭제 위치에 제한 있음).

리스트 vs 스택·큐

  • 리스트: 아무 위치에서나 삽입/삭제 가능
  • 스택: 오직 top에서만 삽입/삭제
  • 큐: 삽입은 rear, 삭제는 front

배열로 리스트 구현

배열 삽입 시 문제

원하는 위치에 삽입하려면 그 이후 데이터를 모두 한 칸씩 뒤로 이동해야 함.
데이터가 많을수록 이동 비용이 커짐 → 비효율적.

배열 삭제 시 문제

특정 위치 삭제 시 그 이후 데이터를 모두 한 칸씩 앞으로 이동해야 함.
데이터 이동이 계속 발생 → 오버헤드 큼.

⚠️ 배열 구현의 단점

삽입/삭제 시마다 데이터가 왔다 갔다 하여 비효율적.
배열 크기를 미리 정해야 하므로 메모리 낭비 또는 부족 가능성 있음.
→ 해결책: 연결 리스트(Linked List)

LINKED LIST

연결 리스트 (Linked List)

노드(Node) 구조

데이터 필드 (Data Field)

실제 데이터(값)를 저장하는 공간.

링크 필드 (Link Field)

다음 노드의 메모리 주소를 저장하는 포인터.
마지막 노드의 링크는 NULL.

10
→ 200번지
→
20
→ 350번지
→
30
NULL

헤드(head) 포인터 → 첫 번째 노드 가리킴

연결 리스트의 종류

종류특징마지막 노드 링크
단순 연결 리스트 각 노드가 다음 노드 주소만 가짐 NULL
원형 연결 리스트 마지막 노드가 첫 번째 노드를 가리킴 첫 번째 노드 주소
이중 연결 리스트 앞 노드 주소 + 뒤 노드 주소 모두 보유 NULL (양방향)

동적 메모리 할당

정적 할당 (Static)

프로그램 실행 전에 메모리 결정.
배열이 대표적 예시.
크기가 고정되어 유연성 부족.

동적 할당 (Dynamic)

프로그램 실행 도중에 필요한 만큼 메모리 할당.
연결 리스트가 대표적 예시.
malloc()으로 할당, free()로 해제.

#include <stdlib.h> typedef int element; typedef struct ListNode { element data; // 데이터 필드 struct ListNode *link; // 다음 노드 주소 (없으면 NULL) } ListNode; // 동적 할당으로 새 노드 생성 ListNode *node = (ListNode *)malloc(sizeof(ListNode)); node->data = 10; node->link = NULL;
📌 연결 리스트의 장점
  • 삽입/삭제 시 데이터를 이동시킬 필요 없음 → 링크(주소)만 변경
  • 크기가 미리 정해지지 않음 → 필요할 때마다 동적 할당
  • 연속된 메모리 공간 불필요 → 메모리 어디에든 저장 가능
LINKED LIST 구현

연결 리스트 삽입·삭제·스택·큐 구현

맨 앞에 삽입 (insert_front)

1
동적 할당: malloc()으로 새 노드 생성
2
데이터 저장: 새 노드의 data 필드에 값 저장
3
링크 연결: 새 노드의 link → 기존 head가 가리키던 노드
4
헤드 갱신: head → 새 노드 (head 포인터 변경)
※ head를 변경하려면 **head 또는 ListNode**로 주소의 주소를 전달해야 함

중간에 삽입

1
삽입할 위치의 이전 노드(prev) 를 찾음
2
새 노드의 link → prev의 다음 노드
3
prev의 link → 새 노드
⚠️ 순서가 중요! 3번을 먼저 하면 기존 링크를 잃어버림

노드 삭제

1
삭제할 노드의 이전 노드(prev) 주소를 알아야 함
2
prev의 link → 삭제할 노드의 다음 노드 (연결을 건너뜀)
3
free(삭제할노드) → 동적 할당 해제
⚠️ 헤드 포인터와 이중 포인터

함수 안에서 head 포인터 값 자체를 바꾸려면 포인터의 포인터 (ListNode **head)로 주소를 전달해야 함.
단순히 ListNode *head를 넘기면 복사본이 되어 원본 head가 변경되지 않음.

두 리스트 합치기 (concatenate)

1
head1 == NULL이면 head2를 그대로 반환
2
head2 == NULL이면 head1을 그대로 반환
3
head1의 마지막 노드까지 순회 (while로 link != NULL 체크)
4
마지막 노드의 link → head2 (두 리스트 연결)

스택의 연결 리스트 구현 (Linked Stack)

구조

스택 노드 = 데이터 필드 + 링크 필드
top 포인터가 최상위 노드를 가리킴
빈 스택: top == NULL

push 연산

① 동적 할당으로 새 노드 생성
② 새 노드의 data = 삽입 값
③ 새 노드의 link = 기존 top
④ top = 새 노드 (top 갱신)

pop 연산

① top 노드의 데이터 저장
② top = top의 link (다음 노드로 이동)
③ 기존 top 노드 free()
④ 저장된 데이터 반환

큐의 연결 리스트 구현 (Linked Queue)

구조

front: 맨 앞 노드 포인터 (dequeue 위치)
rear: 맨 뒤 노드 포인터 (enqueue 위치)
빈 큐: front == rear == NULL

enqueue (연결 리스트)

① 동적 할당으로 새 노드 생성
② 새 노드의 link = NULL
③ rear의 link = 새 노드 (뒤에 연결)
④ rear = 새 노드

dequeue (연결 리스트)

① front 노드의 데이터 저장
② front = front의 link
③ 기존 front 노드 free()
④ front == NULL이면 rear도 NULL로

TREE

트리 (Tree) — 개념과 용어

트리란?

비선형(Non-linear) 자료구조로, 계층적 관계를 표현. 폴더·디렉토리 구조, 조직도가 대표적인 예.

선형 vs 비선형

  • 선형: 배열, 연결 리스트, 스택, 큐 → 순서 O
  • 비선형: 트리, 그래프 → 계층/연결 구조

트리의 특징

  • 노드(node)들과 간선(edge)들로 구성
  • 사이클 없음 (트리와 그래프의 차이)
  • 간선 수 = 노드 수 - 1
  • 루트에서 모든 노드로 경로가 유일함

트리 핵심 용어

루트 (Root)
트리의 최상위 노드. 부모가 없음.
부모 (Parent)
자식 노드를 가진 상위 노드.
자식 (Child)
부모 노드로부터 이어지는 하위 노드.
잎 (Leaf)
자식이 없는 노드 (단말 노드).
높이 (Height)
루트에서 가장 깊은 노드까지의 레벨 수.
레벨 (Level)
루트가 레벨 1, 아래로 내려갈수록 증가.
서브트리 (Subtree)
특정 노드와 그 자손들로 이루어진 트리.
차수 (Degree)
한 노드가 가진 자식의 수.
간선 (Edge)
부모-자식 노드를 연결하는 선.
간선 수 = 노드 수 - 1

BINARY TREE

이진 트리 (Binary Tree)

이진 트리란?

각 노드의 자식 수가 최대 2개인 트리. 왼쪽 자식과 오른쪽 자식으로 구분.

노드 수 — 최솟값

높이가 h일 때 최소 노드 수: h개
(각 레벨에 노드 1개씩만 있을 때)

노드 수 — 최댓값

높이가 h일 때 최대 노드 수: 2h - 1개
(모든 레벨이 꽉 찬 경우)
예) h=3 → 2³-1 = 7개

이진 트리의 종류

종류조건예시 (h=3)
포화 이진트리
Full Binary Tree		 모든 레벨의 노드가 꽉 참. 노드에 번호를 1부터 순서대로 붙일 수 있음. 7개 노드 (2³-1)
완전 이진트리
Complete Binary Tree		 높이 h-1까지 꽉 차고, 마지막 레벨은 왼쪽부터 순서대로 채워짐. 4~7개 노드
경사 이진트리
Skewed Binary Tree		 모든 노드가 한쪽으로만 치우침. h개 노드

배열로 이진 트리 표현

노드에 번호를 붙이면 부모-자식 관계를 배열 인덱스로 계산 가능.

인덱스 규칙 (루트 = 1)

  • 노드 i의 왼쪽 자식: 2 × i
  • 노드 i의 오른쪽 자식: 2 × i + 1
  • 노드 i의 부모: i / 2 (정수 나눗셈)

배열 표현의 단점

경사 이진트리의 경우 메모리 낭비가 심함.
높이 h 경사트리 → 2h개 배열 공간 필요하지만 h개만 사용.

연결 리스트로 이진 트리 표현

TRAVERSAL

이진 트리 순회 (Tree Traversal)

트리의 모든 노드를 체계적으로 방문하는 방법. 루트(R), 왼쪽 서브트리(L), 오른쪽 서브트리(R)의 방문 순서에 따라 구분.

전위 순회 (Preorder)

방문 순서: 루트 → 왼쪽 → 오른쪽
(Root → Left → Right)
루트를 가장 먼저 방문.

중위 순회 (Inorder)

방문 순서: 왼쪽 → 루트 → 오른쪽
(Left → Root → Right)
이진 탐색 트리에서 오름차순 출력.

후위 순회 (Postorder)

방문 순서: 왼쪽 → 오른쪽 → 루트
(Left → Right → Root)
루트를 가장 마지막에 방문.

순회 예제

다음 트리의 순회 결과:

트리 구조
    A
  /   \
 B     C
/ \     /
D  E  F
전위 순회 결과
A → B → D → E → C → F
중위 순회 결과
D → B → E → A → F → C
후위 순회 결과
D → E → B → F → C → A
// 전위 순회: 루트 → 왼쪽 → 오른쪽 void preorder(TreeNode *root) { if (root == NULL) return; printf("%c ", root->data); // 현재 노드 방문 preorder(root->left); // 왼쪽 서브트리 preorder(root->right); // 오른쪽 서브트리 }
📌 순회 핵심 암기 포인트
  • 전위(Pre): 루트가 앞(pre)에 옴 → 루트 → L → R
  • 중위(In): 루트가 가운데(in)에 옴 → L → 루트 → R
  • 후위(Post): 루트가 뒤(post)에 옴 → L → R → 루트
KEYWORDS

전체 핵심 키워드 정리

FIFO
First In First Out. 큐의 동작 원칙 — 먼저 들어온 것이 먼저 나감.
enqueue / dequeue
enqueue: 큐에 삽입(rear에). dequeue: 큐에서 삭제(front에서).
front / rear
front: 삭제 위치 포인터. rear: 삽입 위치 포인터. 초기값 -1.
원형 큐
나머지(%) 연산으로 인덱스 순환. 선형 큐의 공간 낭비 해결.
덱 (Deque)
Double-ended Queue. 앞뒤 양쪽에서 삽입·삭제 가능.
ADT
Abstract Data Type. 구현 방법보다 기능(인터페이스)을 먼저 정의하는 개념.
노드 (Node)
연결 리스트의 기본 단위. 데이터 필드 + 링크 필드(다음 주소).
동적 할당
malloc()으로 실행 중 메모리 할당. free()로 해제. 연결 리스트에 필요.
헤드 포인터
연결 리스트의 첫 번째 노드를 가리키는 포인터.
루트 (Root)
트리의 최상위 노드. 부모가 없음.
포화 이진트리
모든 레벨이 꽉 찬 이진 트리. 높이 h → 2ʰ-1개 노드.
완전 이진트리
마지막 레벨만 왼쪽부터 채워진 이진 트리. 배열로 표현하기 적합.

2. 선형 큐에서 isEmpty 조건으로 올바른 것은?
① rear == MAX_SIZE - 1
② front == rear
③ front == 0
④ rear == 0

② front == rear
③ (rear + 1) % MAX == front

③ 인덱스로 원소에 접근할 수 없다
