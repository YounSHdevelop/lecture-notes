알고리즘 성능 분석과 복잡도

빅5 표기법 · 시간복잡도 · 순환함수(재귀)

📌 학습목표 📊 핵심요약 🕐 재귀흐름 ⚡ 핵심캐치 📖 키워드 ✏️ 연습문제

📌학습 목표

1
알고리즘의 성능을 분석하기 위해 복잡도(연산 횟수)를 계산하는 방법을 이해한다.
2
빅5 표기법(Big-O, Big-Ω, Big-Θ, little-o, little-ω)으로 복잡도를 간결하게 표현할 수 있다.
3
시간복잡도의 최선·평균·최악의 경우를 구분하고, 분석 시 최악의 경우를 기준으로 삼는 이유를 설명할 수 있다.
4
순환함수(재귀)의 작동 원리를 이해하고, 팩토리얼 예제를 직접 추적(trace)할 수 있다.
5
순환과 반복의 장단점을 비교하여 상황에 맞는 방법을 선택할 수 있다.

Θ(f(n))

• 이유: n이 클 때 나머지 무의미

🔄 순환함수(재귀) vs 반복 비교

🔄 순환함수 (Recursion)

함수가 자기 자신을 호출하는 방식

int factorial(int n) { if (n == 0) return 1; // 기저조건(필수!) return n * factorial(n-1); // 재귀호출 }
  • ✅ 코드가 간결하고 직관적
  • ✅ 트리/그래프 탐색, 분할정복에 효과적
  • ❌ 함수 호출 오버헤드 발생
  • ❌ 깊어질수록 스택 오버플로우 위험
  • ⚠️ 기저조건(종료조건) 반드시 필요

🔁 반복 (Iteration)

반복문(for/while)으로 구현하는 방식

int factorial(int n) { int result = 1; for(int i=1; i<=n; i++) { result *= i; } return result; }
  • ✅ 실행 속도 빠름 (오버헤드 없음)
  • ✅ 메모리 효율 좋음
  • ❌ 복잡한 문제는 코드가 길어짐
  • ❌ 트리/그래프 탐색에 불리
  • ⚠️ 대부분 순환↔반복 변환 가능

🕐factorial(4) 재귀 실행 흐름

재귀 호출이 어떤 순서로 쌓이고 풀리는지 단계별로 추적합니다.

STEP 1 — 호출 시작
factorial(4) 호출
4 ≠ 0 → return 4 × factorial(3) 실행 요청. factorial(3)의 결과를 기다리며 대기 상태로 스택에 쌓임.
STEP 2
factorial(3) → factorial(2) → factorial(1) 연쇄 호출
같은 방식으로 n이 줄어들며 계속 호출. 각 호출은 스택에 차곡차곡 쌓임.
Stack: factorial(4) → factorial(3) → factorial(2) → factorial(1)
STEP 3 — 기저조건 도달 ✅
factorial(0) = 1 반환
n == 0 조건 만족 → 1 반환. 더 이상 재귀 호출 없음. 이제 스택을 역순으로 풀기 시작.
STEP 4 — 역전파 (스택 풀림)
결과값이 역순으로 전달
factorial(1) = 1 × 1 = 1
factorial(2) = 2 × 1 = 2
factorial(3) = 3 × 2 = 6
factorial(4) = 4 × 6 = 24 ← 최종 결과

⚡핵심 캐치 (시험 포인트)

🎯
빅O 계산의 핵심 규칙
복잡도 계산 시 가장 큰 차수 항만 남기고 계수는 버린다.
5n³ + 100n² + 999 → O(n³)
이유: n이 매우 클 때 나머지 항의 영향이 무시될 정도로 작아진다.
🔥
왜 최악의 경우를 사용하는가?
최선은 운이 좋은 경우라 일반화 불가. 평균은 확률 분포 가정이 필요해 복잡. 최악의 경우를 기준으로 하면 어떤 입력에서도 성능이 보장된다.
⚠️
재귀함수의 필수 요소: 기저조건
재귀함수에는 반드시 기저조건(Base Case)이 있어야 한다.
없으면 → 무한 재귀 → 스택 오버플로우(Stack Overflow) 발생!
⚖️
순환 vs 반복 선택 기준
대부분의 순환은 반복으로 변환 가능. 단, 트리 탐색·분할정복(퀵정렬·병합정렬)은 순환이 훨씬 직관적. 단순 반복 작업은 반복문이 메모리 효율 우세.
📏
n이 클 때만 복잡도 차이가 드러남
n이 작을 때는 O(n²)과 O(n log n)의 실제 실행 시간 차이가 미미. n이 커질수록 복잡도 클래스의 차이가 기하급수적으로 벌어진다.
🔄
재귀 호출 = 내부적으로 스택 사용
재귀는 내부적으로 호출 스택(Call Stack)을 사용. 깊이가 깊어질수록 스택 메모리 소비 증가. 반복보다 메모리 효율이 낮을 수 있다.

📖핵심 키워드

Time Complexity
시간 복잡도
알고리즘 실행에 필요한 연산 횟수를 입력 크기 n의 함수로 나타낸 것. 실제 시간이 아닌 연산의 수를 측정.
Big-O Notation
빅오 표기법
알고리즘의 최악의 경우 상한을 표현. 가장 많이 사용되는 복잡도 표기법. O(n), O(n²) 등으로 표기.
Recursion
순환함수 (재귀함수)
함수가 자기 자신을 직접 또는 간접적으로 호출하는 방식. 반드시 기저조건(종료조건)이 필요.
Base Case
기저조건 (종료조건)
재귀함수에서 더 이상 자신을 호출하지 않고 값을 반환하는 조건. 재귀의 종료를 담당.
Call Stack
호출 스택
함수 호출 시 정보를 저장하는 스택 메모리. 재귀가 깊어질수록 쌓이고, 과도하면 Stack Overflow 발생.
Best / Average / Worst Case
최선 / 평균 / 최악의 경우
입력에 따른 성능 구분. 일반적으로 최악의 경우(Big-O)를 기준으로 분석.
Complexity Analysis
복잡도 분석
알고리즘의 효율성을 이론적으로 측정하는 방법. 하드웨어와 무관하게 알고리즘 자체의 성능을 비교 가능.
Stack Overflow
스택 오버플로우
재귀 호출이 무한히 반복되거나 너무 깊어져 스택 메모리가 초과될 때 발생하는 오류.
Factorial
팩토리얼
n! = n × (n-1) × … × 1 (단, 0! = 1). 재귀함수의 대표적 예시. 시간복잡도: O(n)
