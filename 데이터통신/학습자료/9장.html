4동기식 — 문자 위주 vs 비트 위주
문자 위주 (Character-oriented)
바이트 위주라고도 함. 프레임을 바이트(8비트)로 구성되는 문자들의 연속된 열로 간주. 문자 단위로 전송, ASCII 제어 문자 사용. 대표: 1964년 IBM의 BSC. 비트 위주에 비해 비효율적이라 거의 사용되지 않음.
비트 위주 (Bit-oriented)
전송 프레임을 비트열로 간주. 1975 IBM SDLC → 1979 ISO HDLC 표준화 → 1981 ITU-T가 HDLC 기반으로 LAPs 개발.
5LAP (Link Access Procedures)
LAP 3종 ★

B = Balanced / D = D channel / M = Modem
💡 LAP 매칭

  • LAPD (LAP for D channel): ISDN의 D채널용
  • LAPM (LAP for Modem): 모뎀용
💡 HDLC로부터 발전된 프로토콜
  • Frame relay, PPP 등

💡 필드 설명
  • SYN (Synchronization): 동기 문자. 2개 이상의 SYN으로 시작. 송수신 장치 간의 문자 동기를 맞추기 위한 전송 제어 문자. 수신 장치에게 새로운 프레임의 도착을 알림
  • SOH (Start of Header): 헤더의 시작
  • Header: 송수신 장치의 주소, 프레임 식별 번호 등과 같은 제어 정보
  • STX (Start of Text): 본문의 시작
  • Data: 실제 데이터 본문
  • ETX (End of Text): 본문의 끝
  • BCC (Block Check Count): 오류 제어용. 1바이트 LRC 또는 2바이트 CRC로 구성

4데이터 투명성 (Data Transparency)
투명성 = ?
DLE 문자 사용
어떠한 비트들의 조합도 제어 정보와 혼동하지 않고 데이터로 전송 가능
💡 핵심 정리
  • 어떠한 비트들의 조합도 제어 정보와 혼동하지 않고 데이터로 전송이 가능해야 함을 의미
  • DLE(Data Link Escape) 문자를 사용하여 확보함
  • 본문 내에 제어 문자가 오는 경우 STX와 ETX 문자 앞에 DLE 문자를 삽입
  • 두 DLE 문자 사이에 있는 모든 문자는 데이터로 취급
  • 투명 영역 내에 제어 문자와 동일한 비트 패턴을 갖는 문자가 있어도 제어 문자로 취급하지 않음
  • 문서 내에 있는 DLE 문자는 DLE 문자를 하나 더 추가

03 🧱 HDLC (High-level Data Link Control)
1HDLC 개요
HDLC 한 줄 ★
1979 ISO 비트위주
SDLC(1975 IBM) 기반 / 점대점·다중점·Half·Full 전이중 모두 지원
💡 핵심 정리
  • 1979년 SDLC를 기반으로 ISO에서 표준화한 비트 위주 프로토콜
  • 점대점, 다중점, Half-duplex, Full-duplex 모두를 지원
  • 흐름 제어: Sliding window 방식 사용
  • 오류 제어: Go-back-N ARQ와 선택적 ARQ 방식 사용
2HDLC 통신국 (Station)
통신국 3종 ★
주국 · 보조국 · 복합국
주국=명령 / 보조국=응답 / 복합국=둘 다
주국 (1차국)
링크의 모든 제어권을 갖는 장치. 보조국들에게 명령(Command)을 보냄.
보조국 (2차국)
주국의 제어를 받고 주국의 명령에 따라 응답(Response)을 보내는 스테이션.
복합국 (조합국)
명령과 응답을 모두 발생할 수 있음. 서로 연결된 대등 장치(Peer Device) 중 하나. 상황에 따라 주국 또는 보조국으로 동작.
정리
주국은 명령을 발생시키고 보조국은 응답을 만들어 냄.
3HDLC 3가지 구성
구성 3종
불균형 · 대칭 · 균형
균형 구성은 점대점에서 양쪽 모두 복합국
💡 구성 매칭
  • 불균형 구성(Unbalanced): 주종 구성(Master/Slave) — 주국 1개 + 보조국 다수
  • 대칭 구성(Symmetrical): 하나의 물리적 스테이션이 두 개의 논리적 스테이션으로 구성 (한쪽이 주국+보조국, 반대쪽이 보조국+주국)
  • 균형 구성(Balanced): 점대점 연결에서 두 스테이션이 모두 복합국인 경우
4HDLC 동작 모드 (NRM · ARM · ABM) ★
동작 모드 3종 ★
NRM · ARM · ABM
정규 응답 / 비동기 응답 / 비동기 균형 — "누가 링크를 제어할 것인가"
NRM (Normal Response Mode)
정규 응답 모드. 표준적인 주국-보조국 관계. 보조국은 전송하기 전에 항상 주국의 허락을 얻어야 함.
ARM (Asynchronous Response Mode)
비동기 응답 모드. 채널이 사용되고 있지 않으면 보조국은 주국의 허가 없이 전송할 수 있음. 보조국으로부터의 모든 전송은 주국을 경유하여 연결됨.
ABM (Asynchronous Balanced Mode)
비동기 균형 모드. 모든 스테이션은 동등하며 점대점으로 연결된 복합국만 사용됨.
전송 시작 권한 정리
NRM = 주국만 / ARM = 둘 중 하나 / ABM = 둘 다.
구분정규 응답 모드비동기 응답 모드비동기 균형 모드
스테이션 종류주국 및 보조국주국 및 보조국복합국
전송 시작 권한주국둘 중 하나둘 다

Flag

💡 필드 설명
  • Flag: 프레임의 시작과 끝을 나타내는 8비트로 프레임의 동기를 제공함. 비트 패턴이 '01111110'이며 수신기를 위한 동기화 패턴의 역할
  • Address: 프레임을 송신하거나 수신하는 종국을 식별하기 위한 주소 필드. 주국 송신 시 목적지 보조국 주소, 주국 수신 시 발신지 보조국 주소
  • Control: 프레임 종류를 식별하기 위해 사용
  • Information(data): 실제 전송할 데이터
  • FCS (Frame Check Sequence): 프레임 전송 도중 오류 검사. 주로 CRC(16비트 또는 32비트) 사용
I-frame (정보)
사용자 데이터 전송 및 사용자 데이터에 관련된 제어정보 전송. Control: 0 + N(S) + P/F + N(R).
S-frame (감시)
제어정보의 전송에만 사용. 데이터 링크 계층의 흐름제어와 오류제어에 사용. Control: 10 + Code + P/F + N(R).
U-frame (무번호)
시스템 관리를 위해 예약. 링크 자체를 관리할 목적의 정보 전송. Control: 11 + Code + P/F + Code.
제어 필드 약자
N(S) = 현재 전송 프레임 번호 / N(R) = 다음에 받기 원하는 프레임 번호 / P/F = 폴 or 마지막 / Code = HDLC 명령/응답 2진 코드.
6피기백킹 (Piggybacking)

목말 태우기
I-프레임에 ACK 제어정보를 합쳐서 보냄 — 별도 응답 프레임 불필요
💡 핵심 정리
  • 양방향 데이터 교환에서 스테이션2는 스테이션1로부터 받은 데이터에 대한 응답을 별도의 응답 프레임을 사용하지 않고 자신의 I-프레임의 제어 필드를 이용하여 보낼 수 있음
  • I-프레임에 제어 정보를 합쳐서 보내는 것을 목말 태우기에 비유한 것
7P/F (Poll/Final) 비트
P 비트
명령 프레임에 표시. 보조국이나 상대 복합국에 응답을 요구. 주국 또는 복합국은 P=1인 명령 송신 후 응답(F=1)을 수신할 때까지 P=1인 명령을 송신할 수 없다.
F 비트
응답 프레임에 표시. P=1인 명령에 대한 응답으로 사용. P=1인 명령 수신 시 보조국·복합국은 F=1인 응답 송신 후 다음 P=1 명령 수신까지 F=1을 송신할 수 없음. 보조국의 마지막 응답을 표시할 때도 사용.

💡 핵심 정리

전이중 데이터 전송
복합국 A와 B 간에 논리적인 연결이 이루어지면 데이터 전송 단계. 흐름 제어와 오류 제어를 수행하면서 I-프레임을 교환.
RNR 흐름 제어
데이터 전송 단계에서 수신 스테이션의 버퍼가 넘치지 않도록 슬라이딩 윈도뿐 아니라 RNR을 이용한 흐름 제어도 병행하여 수행.
REJ 오류 제어
I-프레임에 오류 발생 시 REJ 명령이나 타임아웃을 이용하여 오류 복구. Go-back-N ARQ를 가정.
폴링 데이터 전송
먼저 NRM이 되어야 함. 주국이 SNRM 명령을 보조국에 전송하여 링크 설정 요구 → 보조국 UA 응답.

  • LAPB: X.25 프로토콜과 ISDN의 B채널에서 사용 (비동기 균형 모드, ABM)
  • LAPD: ISDN의 D채널에서 사용 (비동기 균형 모드, ABM)

💡 핵심 정리
  • ESC(escape) 문자인 0x7D를 사용하여 바이트 스터핑을 수행. 0x는 16진수를 의미
  • 플래그를 제외한 프레임 내부에 01111110 (0x7E)이 나타나면 0x5E로 대치되어 전송
  • 수신 측에서는 프레임 내부에 0x7D이 나오면 바이트 스터핑으로 판단하여 0x7D를 제거하고 원래 데이터를 복원
  • 플래그를 제외한 프레임 내부에 ESC 문자인 01111101 (0x7D)이 있으면 0x5D로 대치
  • 0x20보다 작은 값은 무조건 바이트 스터핑을 수행 — 모뎀의 직렬 드라이버가 0x20보다 작은 값을 ASCII 제어 문자로 인식하는 것을 방지
▸ 0x7E (Flag) 처리: 01111110 ← 0x7E ⊕ 00100000 ← 0x20 01011110 ← 0x5E (전송) ▸ 0x7D (ESC) 처리: 01111101 ← 0x7D ⊕ 00100000 ← 0x20 01011101 ← 0x5D (전송)

PPP 처리 과정 ★
LCP → AP → NCP
링크 설정(LCP) → 인증(PAP/CHAP) → 네트워크 설정(NCP) → 패킷 송수신 → 해제
💡 PPP 3개 프로토콜
  • LCP (Link Control Protocol): 두 기기 간 링크의 설정, 유지, 구성, 해제를 담당
  • AP (Authentication Protocol): 연결을 위한 사용자의 인증 절차를 수행 (PAP / CHAP)
  • NCP (Network Control Protocol): 링크 설정과 인증 완료 후, 상위 계층에서 오는 데이터를 PPP 프레임으로 캡슐화하여 전송. IPCP(Internet Protocol Control Protocol)가 IP 주소 할당 수행
💡 LCP 패킷 코드 (Protocol = 0xC021)
  • 0x01 Configure-request · 0x02 Configure-ack · 0x03 Configure-nak · 0x04 Configure-reject
  • 0x05 Terminate-request · 0x06 Terminate-ack · 0x07 Code-reject · 0x08 Protocol-reject
  • 0x09 Echo-reject · 0x0A Echo-reply · 0x0B Discard-request
6인증 프로토콜 — PAP vs CHAP ★
PAP (Password Authentication Protocol)
Protocol 값 0xC023. 패스워드를 전달하여 인증을 획득하는 방법. 코드: 1=request, 2=ack, 3=nak. 패스워드가 전송로 상에 노출됨.
CHAP (Challenge Handshake AP)
Protocol 값 0xC223. PAP보다 높은 보안 제공. challenge → response → success/failure 방식. 패스워드가 전송로 상에 노출되지 않으므로 더 안전.
PAP 메시지 종류
authentication_request ↔ authentication_ack 또는 nak.
CHAP 메시지 종류
시스템→사용자 challenge / 사용자→시스템 response / 시스템→사용자 success 또는 failure.

▪ 서술형 연습

Q23.문자 위주 프로토콜과 비트 위주 프로토콜의 차이를 설명하시오.
▸ 문자 위주 프로토콜: 바이트 위주라고도 하며, 프레임을 바이트(8비트) 단위로 구성된 문자들의 연속된 열로 간주. ASCII 제어 문자를 사용한다. 대표적으로 1964년 IBM이 개발한 BSC가 있으며, 비효율적이라 거의 사용되지 않는다.
▸ 비트 위주 프로토콜: 전송 프레임을 비트열로 간주한다. 1975년 IBM의 SDLC를 시작으로 1979년 ISO가 HDLC를 표준화했으며, 이후 ITU-T가 LAPs(LAPB/LAPD/LAPM)를 개발했다. Frame relay, PPP 등도 HDLC에서 발전한 프로토콜이다.
Q24.BSC의 데이터 투명성 보장 방법을 설명하시오.
▸ 데이터 투명성은 어떠한 비트 조합도 제어 정보와 혼동하지 않고 데이터로 전송될 수 있어야 함을 의미한다.
▸ BSC는 DLE(Data Link Escape) 문자(10H)를 사용하여 확보한다.
▸ 본문 내에 제어 문자가 오는 경우 STX와 ETX 문자 앞에 DLE 문자를 삽입하며, 두 DLE 문자 사이에 있는 모든 문자는 데이터로 취급한다.
▸ 문서 내에 있는 DLE 문자는 DLE 문자를 하나 더 추가해 데이터임을 표시한다.
Q25.HDLC의 NRM, ARM, ABM 동작 모드를 비교 설명하시오.
▸ NRM (정규 응답 모드): 표준적인 주국-보조국 관계. 보조국은 전송 전에 항상 주국의 허락을 얻어야 함. 전송 시작 권한 = 주국만.
▸ ARM (비동기 응답 모드): 채널이 사용되지 않으면 보조국이 주국 허가 없이 전송 가능. 단, 보조국으로부터의 모든 전송은 주국을 경유해 연결됨. 전송 시작 권한 = 둘 중 하나.
▸ ABM (비동기 균형 모드): 모든 스테이션이 동등하며 점대점으로 연결된 복합국만 사용. 전송 시작 권한 = 둘 다. LAPB·LAPD가 이 모드로 동작.
Q26.HDLC의 비트 스터핑 동작을 설명하시오.
▸ HDLC는 프레임 내의 어디서든지 플래그 비트 01111110이 나타나지 않도록 보장해야 한다.
▸ 이를 위해 송신기는 연속된 5개의 1이 있으면 다섯 번째 다음에 0을 삽입하며, 수신기는 삽입된 0을 제거한다.
▸ 예: 원본 11111111111111(1×14) → 송신 1111101111101111(5개 1마다 0 삽입) → 수신 측에서 0을 제거하여 복원.
▸ 이로써 데이터 내부에 플래그와 동일한 패턴이 우연히 나타나는 것을 방지할 수 있다.
Q27.PPP의 처리 과정을 LCP, AP, NCP를 사용하여 설명하시오.
▸ ① 링크 설정 (LCP): 두 기기 간 링크의 설정, 유지, 구성, 해제를 담당. configuration_request ↔ configuration_ack 교환.
▸ ② 인증 (AP): 연결을 위한 사용자 인증 절차 수행. PAP(0xC023)는 패스워드를 직접 전송하므로 노출되며, CHAP(0xC223)는 challenge → response → success/failure로 패스워드를 노출시키지 않아 더 안전.
▸ ③ 네트워크 설정 (NCP): 링크 설정·인증 완료 후, 상위 계층 데이터를 PPP 프레임으로 캡슐화하여 전송. IPCP(Internet Protocol Control Protocol)가 IP 주소를 할당.
▸ 데이터 송수신 후 NCP → LCP 순으로 terminate_request로 해제.
Q28.HDLC의 비트 스터핑과 PPP의 바이트 스터핑을 비교 설명하시오.
▸ HDLC 비트 스터핑: 비트 단위로 동작. 연속된 5개의 1이 있으면 다섯 번째 다음에 0을 삽입하여 플래그(01111110)와의 충돌을 방지. 수신 측은 삽입된 0을 제거.
▸ PPP 바이트 스터핑: 바이트 단위로 동작. ESC 문자(0x7D)를 사용하여 프레임 내부의 0x7E(플래그)와 0x7D(ESC)를 각각 0x5E, 0x5D로 대치하여 전송. 수신 측에서 0x7D를 만나면 다음 바이트의 6번째 비트를 반전시켜 원래 값을 복원.
▸ 또한 PPP는 0x20보다 작은 값은 무조건 바이트 스터핑을 수행해 모뎀 직렬 드라이버가 ASCII 제어 문자로 오인식하는 것을 방지한다.

X.25/ISDN B(ABM) · ISDN D(ABM) · 모뎀(부분집합).
PPP 개발 ★
SLIP 보완 · IETF
SLIP은 IP만 지원. 전화선·케이블 인터넷 접속용.
PPP 기능
검출·압축·인증 O / 재전송·흐름 X
오류 검출, 데이터 압축, 사용자 인증만 제공.
PPP 프레임 ★
7E·FF·03·Proto·1500B·CRC·7E
Flag·Address(브로드캐스트)·Control·Protocol·Payload·FCS.
PPP Protocol 값 ★
C021·C023·C223·8021·0021
LCP·PAP·CHAP·NCP·IP data.
PPP 바이트 스터핑
ESC = 0x7D
0x7E→0x5E, 0x7D→0x5D. 0x20보다 작은 값은 무조건 스터핑.
PPP 처리 ★
LCP → AP → NCP
링크 설정 → 인증 → 네트워크 캡슐화. NCP의 IPCP가 IP 할당.
PAP vs CHAP ★
패스워드 노출 / Challenge-Response
CHAP는 패스워드 미노출 → PAP보다 보안 우수.
