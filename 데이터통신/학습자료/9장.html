01 🗂️ 데이터링크 프로토콜의 분류

데이터링크 프로토콜 = ?
회선·흐름·오류 제어 기능을 실현하는 규칙
회선 제어, 흐름 제어, 오류 제어 등의 기능을 실현하기 위한 규칙을 포함. 전송 제어 프로토콜이라고도 한다.
2프로토콜 분류 체계 ★★
대분류중분류대표 프로토콜
비동기식 프로토콜—XMODEM, YMODEM, ZMODEM, BLAST, Kermit
동기식 프로토콜문자 위주 프로토콜BSC
비트 위주 프로토콜SDLC, HDLC, LAPs, SLIP, PPP, LANs
3비동기식 데이터링크 프로토콜
  • 통신이 송신 측과 수신 측 사이의 기계적인 클록(clock)의 동기화 없이 이루어짐
  • 송신 측에서 프레임의 시작과 끝을 알리는 수신 측과 약속된 비트를 삽입
  • 수신 측에서는 추가된 비트를 확인하여 데이터 부분만 추출
  • 종류 : XMODEM, YMODEM, ZMODEM, BLAST, Kermit / 거의 사용되지 않음
4동기식 — 문자 위주 vs 비트 위주 ★★
문자 위주 프로토콜 (character-oriented)
바이트 위주 프로토콜이라고도 함. 프레임을 바이트(8비트)로 구성되는 문자들의 연속된 열로 간주. 문자 단위로 전송, ASCII 제어 문자 사용. 1964년 IBM이 개발한 BSC. 비트 위주에 비해 비효율적이라 거의 사용되지 않음.
비트 위주 프로토콜 (bit-oriented)
전송 프레임을 비트열로 간주. 1975년 IBM의 SDLC → 1979년 ISO가 HDLC 표준화 → 1981년부터 ITU-T에서 HDLC 기반 LAPs(LAPB, LAPD, LAPM) 개발.
💡 LAP (Link Access Procedures) & HDLC 발전
  • LAPB(LAP Balanced) : X.25 패킷교환망과 ISDN의 B채널용
  • LAPD(LAP for D channel) : ISDN의 D채널용
  • LAPM(LAP for Modem) : 모뎀용
  • HDLC로부터 발전된 프로토콜 : Frame relay, PPP
02 📜 BSC (Binary Synchronous Communication)
1BSC의 특징 ★
  • 1964년 IBM에서 개발한 문자 위주 프로토콜
  • 점대점과 다중점 모두를 지원
  • 정지-대기 ARQ 흐름 제어와 오류 제어를 사용하는 반이중 전송을 지원
  • 전이중 전송과 연속적 ARQ를 지원하지 않음 ★

3BSC의 전송 제어 문자 (16진수 표기) ★
  • 전송 블록 형식화 : 프레임들의 크기를 결정(SYN, SOH, STX, ETB, ETX 등의 제어 문자)
  • 스테이션 간의 대화 : 반이중 통신으로 프레임을 교환하기 위해 사용(ENQ)
  • 투명 모드 제어 : 사용자 데이터 투명성 보장(DLE)
  • 코드는 16진수(Hex) 0~9, A, B, C, D, E, F. 0x 또는 H로 표시

4데이터 투명성 (Data transparency) ★
  • 어떠한 비트들의 조합도 제어 정보와 혼동하지 않고 데이터로 전송이 가능해야 함
  • DLE(Data Link Escape) 문자를 사용하여 확보함
  • 본문 내에 제어 문자가 오는 경우 STX와 ETX 문자 앞에 DLE 문자를 삽입
  • 두 DLE 문자 사이에 있는 모든 문자는 데이터로 취급함
  • 투명 영역 내에 제어 문자와 동일한 비트 패턴을 갖는 문자가 있어도 제어 문자로 취급하지 않음
  • 문서 내에 있는 DLE 문자는 DLE 문자를 하나 더 추가

03 🔗 HDLC (High-level Data Link Control)
1HDLC의 특징 ★
  • 1979년 SDLC를 기반으로 ISO에서 표준화한 비트 위주 프로토콜
  • 점대점, 다중점, Half-duplex, Full-duplex 모두를 지원
  • 흐름 제어 : Sliding window 방식 사용
  • 오류 제어 : Go-back-N ARQ와 선택적 ARQ 방식 사용
2HDLC를 구성하는 통신국 (Station) ★
주국 (1차국)
링크의 모든 제어권을 갖는 장치. 보조국들에게 명령(Command)을 보냄.
보조국 (2차국)
주국의 제어를 받고 주국의 명령에 따라 주국에게 응답(Response)을 보내는 스테이션. 주국은 명령을 발생시키고 보조국은 응답을 만들어 냄.
복합국 (조합국)
명령과 응답을 모두 발생할 수 있음. 서로 연결된 대등 장치(Peer Device) 중 하나로, 상황에 따라 주국 또는 보조국으로 동작.
3HDLC의 3가지 구성
  • 불균형형 구성(Unbalanced) : 주종 구성(Master/slave configuration)
  • 대칭 구성(Symmetrical) : 하나의 물리적 스테이션이 두 개의 논리적 스테이션으로 구성
  • 균형형 구성(Balanced) : 점대점 연결에서 두 스테이션이 모두 복합국인 경우
4HDLC 동작 모드 (NRM·ARM·ABM) ★★
누가 링크를 제어할 것인가?
NRM · ARM · ABM
3가지 동작 모드
NRM (Normal Response Mode) — 정규 응답모드
표준적인 주국-보조국 관계. 보조국은 전송하기 전에 항상 주국의 허락을 얻어야 함.
ARM (Asynchronous Response Mode) — 비동기 응답모드
채널이 사용되고 있지 않으면 보조국은 주국의 허가 없이 전송할 수 있음. 보조국으로부터의 모든 전송은 주국을 경유하여 연결됨.
ABM (Asynchronous Balanced Mode) — 비동기 균형모드
모든 스테이션은 동등하며 점대점으로 연결된 복합국만 사용됨.
구분정규 응답 모드(NRM)비동기 응답 모드(ARM)비동기 균형 모드(ABM)
스테이션 종류주국 및 보조국주국 및 보조국복합국
전송 시작 권한주국둘 중 하나둘 다

I-frame (Information frame) — 정보 프레임
사용자 데이터의 전송 및 사용자 데이터에 관련된 제어 정보 전송에 사용. (Flag·Address·Control·Information·FCS·Flag)
S-frame (Supervisory frame) — 감시 프레임
제어 정보의 전송에만 사용, 데이터 링크 계층의 흐름 제어와 오류 제어에 사용됨. (Information 필드 없음)
U-frame (Unnumbered frame) — 무번호 프레임
시스템 관리를 위해 예약된 것, 링크 자체를 관리할 목적의 정보를 전송. (네트워크 관리 정보는 없을 수도 있음)
6HDLC 필드 & 제어 필드 ★★
필드설명
Flag프레임의 시작과 끝을 나타내는 8비트로 프레임의 동기를 제공, 비트 패턴 01111110
Address프레임을 송신·수신하는 종국을 식별하기 위한 주소. 주국이 송신하면 목적지 보조국 주소, 주국이 수신하면 발신지 보조국 주소.
Control프레임 종류를 식별하기 위해 사용
Information(data)실제 전송할 데이터
FCS프레임 전송 도중 오류가 발생하였는지를 검사함. 주로 CRC(16비트 또는 32비트) 사용
[제어 필드 구조] I-프레임 : 0 │ N(S) │ P/F │ N(R) S-프레임 : 1 0 │ Code │ P/F │ N(R) U-프레임 : 1 1 │ Code │ P/F │ Code
  • N(S) : 현재 전송하는 프레임의 순서 번호
  • N(R) : 다음에 전송받기를 원하는 프레임의 순서 번호
  • P/F : 폴링 또는 마지막 프레임인지 표시
  • Code : HDLC의 명령/응답에 대한 2진 코드

8데이터 투명성 — 비트 스터핑 (Bit stuffing) ★★
왜 필요한가?
프레임 안에 Flag(01111110)가 나타나면 안 됨
프레임 내의 어디서든지 플래그 비트 01111110이 나타나지 않도록 보장해야 함 → 비트 스터핑 수행
  • 송신기는 연속된 5개 이상의 1이 있으면 다섯 번째 다음에 0을 삽입한다.
  • 수신기에서는 삽입된 0을 제거하면 된다.
원래 데이터: 111111111111 송신 데이터: 11111 0 11111 0 1111 (다섯 번째 1 다음에 0 삽입) 수신 데이터: 111111111111 (삽입된 0 제거 → 복원)
9피기백킹 & P/F 비트
피기백킹 (Piggybacking)
양방향 데이터 교환에서 스테이션 2는 스테이션 1로부터 받은 데이터에 대한 응답을 별도의 응답 프레임 없이 자신의 I-프레임의 제어 필드를 이용하여 보냄. I-프레임에 제어 정보를 합쳐서 보내는 것을 목말 태우기에 비유.
P/F (Poll/Final) 비트
P 비트는 명령 프레임에 표시되며 보조국·상대 복합국에 응답을 요구. F 비트는 응답 프레임에 표시되며 P=1인 명령에 대한 응답으로 사용. 보조국의 마지막 응답을 표시할 때도 사용.
10HDLC 동작 과정 ★
  • 데이터링크 연결 설정 : SNRM, SARM, SABM 중에서 한 프레임을 전달하고 응답은 UA로 받음
  • 데이터링크 해제 : DISC 프레임을 보조국에 전달하고 수신 측은 UA로 응답
  • 전이중 데이터 전송 : 복합국 A와 B 간 논리적 연결이 이루어지면 흐름·오류 제어를 하면서 I-프레임을 교환
  • RNR을 이용한 흐름 제어 : 수신 버퍼가 넘치지 않도록 슬라이딩 윈도우 + RNR 병행
  • REJ를 이용한 오류 제어 : I-프레임 오류 시 REJ 명령이나 타임아웃으로 복구(Go-back-N 가정)
  • 폴링/셀렉션 : 정규 응답 모드(NRM)에서 SNRM → UA로 링크를 설정하고 전송
11HDLC 응용 프로토콜
  • LAPB : X.25 프로토콜과 ISDN의 B채널에서 사용 (비동기 균형 모드, ABM)
  • LAPD : ISDN의 D채널에서 사용 (비동기 균형 모드, ABM)
  • LAPM : 모뎀을 위한 단순화된 HDLC 부분집합
04 🌐 PPP (Point-to-Point Protocol)
1점대점 링크 프로토콜 — SLIP vs PPP ★
  • 가정에 있는 컴퓨터를 전화선이나 케이블을 이용하여 인터넷에 접속하기 위해서는 점대점 링크 프로토콜이 필요
SLIP (Serial Line Internet Protocol)
IP만을 지원하는 점대점 링크 프로토콜.
PPP (Point-to-Point Protocol)
SLIP의 단점을 보완하여 IETF에서 개발. 전화선을 이용한 인터넷 접속에 널리 사용.
💡 PPP의 특징
  • 비동기식과 동기식 모두 지원
  • 데이터링크 계층 프로토콜
  • 오류 검출, 데이터 압축, 사용자 인증 기능 제공
  • 오류 복구를 위한 재전송과 흐름 제어는 제공하지 않음 ★

FlagHDLC와 같이 프레임의 시작과 끝 표시(동기화). 01111110 사용.

Control00000011. 순서 번호를 사용하지 않으므로 흐름 제어나 오류 제어를 수행하지 않음.
Protocol페이로드 필드에 포함된 정보의 프로토콜 종류를 나타냄. LCP:0xC021, PAP:0xC023, CHAP:0xC223, NCP:0x8021, IP data:0x0021
Payload최대 1,500바이트를 갖는 사용자 데이터
FCS2바이트 또는 4바이트의 CRC
3바이트 스터핑 (Byte stuffing) ★
  • ESC(escape) 문자인 0x7D를 사용하여 바이트 스터핑을 수행. 0x는 16진수를 의미.
  • 플래그를 제외한 프레임 내부에 01111110(0x7E)이 나타나면 0x5E로 대치되어 전송된다. (0x7E ⊕ 0x20 = 0x5E)
  • 수신 측에서는 프레임 내부에 0x7D가 나오면 바이트 스터핑으로 판단하여 0x7D를 제거하고 원래 데이터를 복원한다.
  • 플래그를 제외한 프레임 내부에 ESC 문자인 01111101(0x7D)이 있으면 0x5D로 대치되어 전송되고, 수신 측에서 복원된다.
  • 0x20보다 작은 값은 무조건 바이트 스터핑을 수행한다. 모뎀의 직렬 드라이버가 0x20보다 작은 값을 ASCII 제어 문자로 인식하는 것을 방지하기 위해서다.
★ HDLC 비트 스터핑 vs PPP 바이트 스터핑
HDLC는 비트 단위(연속 5개 1 다음 0 삽입), PPP는 바이트(문자) 단위(ESC=0x7D로 대치)로 투명성을 확보한다.
4PPP 처리 과정과 프로토콜 (LCP·AP·NCP) ★★
[PPP 프로토콜 처리 절차] 사용자 ↔ 시스템 ① configuration_request / ack → 링크 설정 (LCP) ② authentication_request / ack → 인증 (PAP 또는 CHAP) ③ configuration_request / ack → 네트워크 설정 (NCP) ④ packet → 패킷 송수신 (NCP) ⑤ terminate_request / ack → 네트워크 해제 (NCP) ⑥ terminate_request / ack → 링크 해제 (LCP)
LCP (Link Control Protocol) — 링크 제어
두 기기 간 링크의 설정·유지·구성·해제를 담당. Protocol = 0xC021. Code 예) 0x01 Configure-request, 0x05 Terminate-request 등.
AP (Authentication Protocol) — 인증
연결을 위한 사용자의 인증 절차를 수행.
· PAP(Password Authentication Protocol, 0xC023): 패스워드를 전달하여 인증 획득.
· CHAP(Challenge Handshake Authentication Protocol, 0xC223): PAP보다 높은 보안. 패스워드가 전송로 상에 노출되지 않아 더 안전. challenge → response → success/failure.
NCP (Network Control Protocol) — 네트워크 제어
링크가 설정되고 인증이 완료된 다음, 상위 계층에서 오는 데이터를 PPP 프레임으로 캡슐화하여 전송. IPCP(Internet Protocol Control Protocol, 0x8021) — IP 주소 할당.

▪ 단답형

Q13.HDLC 프레임에서 시작과 끝을 나타내는 8비트 플래그의 비트 패턴을 쓰시오.

Q14.HDLC 제어 필드에서 다음에 전송받기를 원하는 프레임의 순서 번호를 나타내는 값(기호)은?
N(R) — N(S)는 현재 전송하는 프레임의 순서 번호, N(R)은 다음에 전송받기를 원하는 프레임의 순서 번호이다.
Q15.I-프레임의 제어 필드를 이용해 응답을 함께 보내는 것을 무엇이라 하는가? (목말 태우기에 비유)
피기백킹(Piggybacking) — 별도의 응답 프레임 없이 자신의 I-프레임 제어 필드(N(R))를 이용해 응답을 보낸다.
Q16.PPP에서 바이트 스터핑에 사용하는 ESC 문자의 16진수 값은?
0x7D — 프레임 내부에 0x7E(01111110)이 나타나면 0x5E로, ESC 0x7D가 있으면 0x5D로 대치한다.
Q17.PPP에서 IP 주소를 할당하는 네트워크 제어 프로토콜(약어)은?
IPCP (Internet Protocol Control Protocol) — NCP의 하나로 Protocol 값은 0x8021이며 IP 주소를 할당한다.

▪ 서술형 연습

Q18.문자 위주 프로토콜과 비트 위주 프로토콜의 차이점을 설명하시오.
▸ 문자 위주 프로토콜: 프레임을 바이트(8비트)로 구성되는 문자들의 연속된 열로 간주하고, 문자 단위로 전송하며 ASCII 제어 문자를 사용한다. 대표적으로 1964년 IBM의 BSC가 있으며, 비트 위주에 비해 비효율적이라 거의 사용되지 않는다.
▸ 비트 위주 프로토콜: 전송 프레임을 비트열로 간주한다. 1975년 IBM의 SDLC를 시작으로 1979년 ISO가 HDLC를 표준화했고, 이후 LAP·PPP 등으로 발전했다. 문자 단위가 아닌 비트 단위로 처리하므로 효율적이다.
Q19.HDLC의 I-프레임, S-프레임, U-프레임의 용도를 각각 설명하시오.
▸ I-프레임(정보 프레임): 사용자 데이터의 전송 및 사용자 데이터에 관련된 제어 정보 전송에 사용된다.
▸ S-프레임(감시 프레임): 제어 정보의 전송에만 사용되며 데이터 링크 계층의 흐름 제어와 오류 제어에 사용된다. (RR·REJ·RNR·SREJ)
▸ U-프레임(무번호 프레임): 시스템 관리를 위해 예약된 것으로 링크 자체를 관리할 목적의 정보를 전송한다. (SNRM·DISC·UA 등)
Q20.PPP의 처리 과정과 LCP·AP·NCP 세 프로토콜의 역할을 설명하시오.
▸ PPP는 ① 링크 설정 → ② 인증 → ③ 네트워크 설정 → ④ 패킷 송수신 → ⑤ 네트워크 해제 → ⑥ 링크 해제의 순서로 동작한다.
▸ LCP(Link Control Protocol): 두 기기 간 링크의 설정·유지·구성·해제를 담당한다(0xC021).
▸ AP(Authentication Protocol): 연결을 위한 사용자 인증을 수행한다. PAP는 패스워드를 전달하여 인증하고, CHAP는 패스워드가 전송로에 노출되지 않아 더 안전하다.
▸ NCP(Network Control Protocol): 링크·인증 후 상위 계층 데이터를 PPP 프레임으로 캡슐화하여 전송한다. IPCP는 IP 주소를 할당한다(0x8021).
