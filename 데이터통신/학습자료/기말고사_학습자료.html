7장 🔀 다중화 (Multiplexing)
1다중화 개념
핵심 정의
단일 링크 → 여러 신호 동시 전송
링크의 전송 용량이 장치들의 전송량보다 클 때 사용 / 링크(물리적) vs 채널(논리적)
FDM (주파수 분할)
아날로그 신호 다중화. 서로 다른 반송파로 변조. 보호 대역(Guard Band) 필수. AM·FM 라디오, 전화망.
WDM (파장 분할)
광섬유의 아날로그 다중화. 프리즘으로 빛을 결합·분리.
TDM (시분할)
디지털 신호 다중화. 시간을 나눠 공유. 동기(STDM, 고정 슬롯) vs 비동기(Statistical=통계적=지능적).
CDM (코드 분할)
FDM+TDM 혼합. 각 사용자에게 직교 코드 부여. 스펙트럼 확산(FHSS→DSSS 현재 주류). 군사·위성·한국 이동통신.
2TDM 핵심 수치 — 시험 단골!
종류속도채널비고
T-1 (북미)1.544 Mbps24채널1프레임=193비트(24×8+1)
E-1 (한국/유럽)2.048 Mbps30채널음성30+프레임동기1+신호용1=32
DS-0 기본단위64 Kbps—8000샘플/초 × 8비트
★ 단답 예상: 비동기 TDM의 다른 이름 2개
통계적 TDM(Statistical TDM) = 지능적 TDM(Intelligent TDM) = 비동기 TDM. 모두 같은 것!
3스펙트럼 확산 (CDM)
FHSS (주파수 도약)
Frequency Hopping Spread Spectrum. 홉 주기마다 다른 반송 주파수로 변조. 슈도랜덤 코드로 도약 패턴 결정. 과거 주류.
DSSS (직접 순열)
Direct Sequence Spread Spectrum. 칩(Chip) n비트 코드를 각 비트에 곱해 n배 대역 확산. 바커 순열(n=11). 현재 주류.
8장 ⚙️ 데이터링크 제어
1전송 제어 절차 5단계 ★★★ (서술 최빈출)
무조건 암기
회선 → 링크 확립 → 전송 → 링크 해제 → 절단
전용 회선은 ①⑤ 생략 → 3단계(링크 확립→전송→링크 해제)
① 회선 연결→ ② 데이터링크 확립→ ③ 데이터 전송→ ④ 데이터링크 해제→ ⑤ 회선 절단
단계별 설명
  • ① 회선 연결: 물리적 접속. 다이얼로 통신 회선 연결 (교환 회선 전용)
  • ② 데이터링크 확립: 논리적 경로 구성 = 회선 제어 (경쟁 or 폴·셀렉션)
  • ③ 데이터 전송: 오류·순서 제어 수행하며 데이터 전송
  • ④ 데이터링크 해제: 논리적 링크 해제
  • ⑤ 회선 절단: 물리적 접속 절단 (교환 회선 전용)
2데이터링크 3대 제어 기능
회선 제어 (Line Control)
누가 신호를 보낼 것인가? 경쟁 방식 or 폴·셀렉션 방식.
흐름 제어 (Flow Control)
수신 버퍼가 넘치지 않게 송신 속도 조절. 정지-대기 / 슬라이딩 윈도우.
오류 제어 (Error Control)
보낸 대로 잘 받았나? 오류 검출 후 재전송(ARQ) 또는 전진 오류 수정(FEC).
3회선 제어 방식
경쟁 방식 (Contention)
먼저 요구한 장치가 송신 권한. 점대점에 사용. 대표: ALOHA (하와이대, 최초 무선 패킷망). 트래픽 높으면 비효율.
폴-셀렉션 (Poll-Selection)
다중점 방식. 주장치(Primary) + 종장치(Secondary). 폴=주→종 (보낼 데이터? 묻기). 셀렉션=주→종 (데이터 전송). 모든 전송은 주장치를 통해.
4흐름 제어 방식 ★★
RTS/CTS (하드웨어적) ★
EIA-232에서 사용. 모뎀 통신 시 보오율 맞춤. RTS 전송 → CTS ON → 데이터 → CTS OFF. 일반적으로 많이 사용.
Xon/Xoff (소프트웨어적)
컴퓨터↔프린터. 버퍼 full → Xoff(멈춤) → Xon(재개).
정지-대기 (Stop-and-Wait) ★
한 프레임 전송 → ACK 대기 → 다음. 장점: 간단. 단점: 링크 낭비, 비효율.
슬라이딩 윈도우 ★★
ACK 없이 여러 프레임 연속 전송. TCP 사용. 윈도우 크기 16비트(최대 65,535). 전송 효율 좋음.
★ 슬라이딩 윈도우 크기 계산 예
ACK 수신까지 40μs, 프레임 1개 전송 2μs → 윈도우 크기 = 40÷2 = 20
5오류 검출 방식 ★★
패리티 검사 (Parity Check)
1비트 리던던시 추가. 홀수/짝수 패리티. 짝수 개 오류는 검출 불가. 가장 간단하나 약함.
블록 합 검사 (Block Sum)
2차원 패리티(VRC 세로 + LRC 가로). 1비트 오류는 위치까지 찾아 정정 가능. 짝수 개 오류도 LRC로 검출.
CRC (순환 중복 검사) ★★
2진 다항식 나눗셈 → FCS 생성. 수신 측 나머지 0이면 오류 없음. 버스트 오류 검출. 가장 많이 사용. 2계층.
검사합 (Checksum)
세그먼트 합 + 캐리 → 1의 보수. 수신 측 결과 0이면 오류 없음. TCP/UDP 등 3~4계층.
CRC 종류생성 다항식
CRC-16x¹⁶ + x¹⁵ + x² + 1
CRC-CCITTx¹⁶ + x¹² + x⁵ + 1
6ARQ (자동 반복 요청) ★★
ARQ = 흐름제어 + 오류제어의 통합
데이터링크 계층의 대표 오류 정정
오류 검출 → 재전송 요청. 흐름 제어(슬라이딩/정지대기) + 프레임 오류 → ARQ
① Stop-and-Wait ARQ
1프레임 전송 후 ACK/NAK 대기. NAK이면 재전송. 가장 단순, 효율 최저.
② Go-Back-N ARQ ★
오류 프레임부터 이후 모든 프레임 재전송. NAK 2 수신 → 2,3,4 재전송. 제어 간단, 가장 많이 사용.
③ 선택적(Selective) ARQ
오류 프레임만 재전송. NAK 2 수신 → 2만 재전송. 효율적이나 대용량 버퍼·제어 복잡.
후진(BEC) vs 전진(FEC)
BEC(ARQ): 역채널로 재전송 요청. FEC(해밍코드): 스스로 정정, 역채널 불필요, 실시간 통신.
9장 📋 데이터링크 프로토콜 & HDLC
1프로토콜 분류 ★★
대분류중분류대표 프로토콜
비동기식—XMODEM, YMODEM, ZMODEM (거의 미사용)
동기식문자 위주BSC (1964, IBM)
비트 위주SDLC(1975 IBM) → HDLC(1979 ISO) → LAP계열
문자 위주 (Character-oriented)
바이트 위주. 8비트 문자의 연속열로 간주. ASCII 제어 문자 사용. BSC가 대표.
비트 위주 (Bit-oriented)
전송 프레임을 비트열로 간주. SDLC → HDLC → LAPB·LAPD·LAPM → PPP로 발전.
2BSC 특징
  • 1964년 IBM이 개발한 문자 위주 프로토콜
  • 점대점 + 다중점 지원 / 정지-대기 ARQ / 반이중 전송
  • 전이중 전송과 연속적 ARQ 지원하지 않음 ★
  • 프레임: SYN SYN SOH Header STX Data ETX BCC (BCC=LRC 또는 CRC)
  • 데이터 투명성: DLE(Data Link Escape) 문자로 확보
3HDLC 프레임 구조 ★★★ (그릴 줄 알아야 함!)
HDLC 프레임 순서 암기
플·주·제·정·FCS·플
플래그 → 주소부 → 제어부 → 정보부 → FCS → 플래그
플래그01111110
주소부(Address)
제어부(Control)
정보부(Information)
FCS(CRC)
플래그01111110
각 필드 설명
  • 플래그: 01111110 — 프레임 시작·끝 표시
  • 주소부: 보조국 주소 (주→종: 수신지 주소 / 종→주: 발신지 주소)
  • 제어부: N(S)=현재 순서번호, N(R)=다음 기대 순서번호, P/F=폴/마지막 비트
  • 정보부: 사용자 데이터
  • FCS: CRC 오류 검출 코드
★ 시험 출제 — 직접 그릴 수 있어야 함
HDLC 프레임 구조 그리기 연습
종이에 네모 칸 6개를 그리고 순서대로 채워보세요: 플래그 | 주소부 | 제어부 | 정보부 | FCS | 플래그 — 각 필드의 역할도 함께 적을 수 있어야 합니다.
4HDLC 프레임 3가지 유형 ★★
I 프레임 (Information, 정보)
사용자 데이터 전송용. 제어부 MSB=0. N(S)=현재순서, N(R)=피기백킹(응답번호). 흐름·오류 제어 동시 수행.
S 프레임 (Supervisory, 감독)
흐름 제어·오류 제어용. 데이터 없음. S코드: 00=RR(받을 준비 됨), 01=REJ(거절/Go-back-N), 10=RNR(받을 준비 안 됨), 11=SREJ(선택적 거절).
U 프레임 (Unnumbered, 무번호/비번호)
링크 관리용. 연결 설정(SNRM/SARM/SABM→UA) 및 해제(DISC→UA). 순서 번호 없음.
비트 스터핑 (데이터 투명성)
플래그 패턴(01111110) 오인식 방지. 연속된 1이 5개면 다섯 번째 다음에 0 삽입. 수신 측에서 0 제거.
★ HDLC 연결 설정/해제 과정
연결 설정: SNRM / SARM / SABM → UA 응답
연결 해제: DISC → UA 응답
피기백킹(Piggyback): I-프레임의 제어 필드에 응답(N(R))을 함께 보내는 것 = 목말 태우기
5HDLC 통신국·구성·동작 모드
구분종류설명
통신국주국(Primary)명령 전송, 링크 제어
통신국보조국(Secondary)응답 전송
통신국복합국(Combined)주국+보조국 역할 모두
동작 모드NRM (정규 응답)보조국이 주국 허가 받아야만 전송 가능
동작 모드ARM (비동기 응답)보조국이 허가 없이도 전송 가능
동작 모드ABM (비동기 균형)복합국 간 점대점. 서로 대등. 가장 많이 사용.
10장 🌐 LAN 기술 (CSMA/CD · CSMA/CA · 터미널 문제)
1CSMA/CD — 유선 LAN (이더넷) ★★
CSMA/CD = ?
CS(반송파 감지) + MA(다중접근) + CD(충돌 검출)
충돌 감지 후 Jam 신호 전송 → 지수 백오프 → 재전송. 유선에서만 가능(충돌 감지 가능).
CSMA/CD 동작 과정
  1. 전송 전 채널 감지(CS) → 비어있으면 전송
  2. 충돌 발생 시 Jam(재밍) 신호 전송, 카운터 N=N+1
  3. N>15이면 비정상 종료
  4. [0, 2ᴺ-1] 범위의 임의 정수 k × 슬롯타임 대기 후 재시도
최소 프레임 크기
512비트 (64바이트). 전송 시간 Tfr ≥ 2Tp 보장. 이더넷 최대 거리 2,500m.
이더넷 프레임 구조
Preamble(7B) · SFD(1B,10101011) · DA(6B) · SA(6B) · Length(2B) · Data(46~1500B) · CRC(4B, CRC-32).
2CSMA/CA — 무선 LAN ★★ (서술 대비)
CSMA/CA = CSMA/CD 변형
무선 = 충돌 검출 불가 → 충돌 회피(CA)
핵심: NAV(Network Allocation Vector). RTS→CTS→data→ACK 순서.
CSMA/CA 동작 (서술용)
  1. 송신 전 DIFS만큼 대기
  2. RTS(Request To Send) 프레임 전송 → 채널 점유 시간(NAV) 포함
  3. 수신 스테이션이 CTS(Clear To Send) 전송 → 주변 스테이션은 NAV 설정
  4. NAV 기간 동안 다른 스테이션은 전송 시도하지 않음 → 충돌 회피
  5. 데이터 전송 후 ACK 수신 (무선은 ACK 필수)
★ CSMA/CD vs CSMA/CA 핵심 차이
CSMA/CD: 충돌 검출 → 유선 LAN (IEEE 802.3)
CSMA/CA: 충돌 회피 → 무선 LAN (IEEE 802.11) / 반드시 ACK 필요 / NAV가 핵심
3숨겨진 터미널 & 노출된 터미널 ★★ (서술 대비)
🔴 숨겨진 터미널 문제 (Hidden Terminal)
시나리오: A와 C는 직접 통신 불가. B는 A,C 모두와 통신 가능.
→ A가 B에 전송 중 C는 모르고 B에 전송 시도 → 충돌 발생.
해결: A가 RTS 전송 → B가 CTS 전송 → C도 CTS 수신 → NAV 기간 전송 중단.
🟡 노출된 터미널 문제 (Exposed Terminal)
시나리오: B→A 전송 중, C는 B 신호 감지 → 매체 사용 중이라 판단 → D에 전송하지 않음.
→ 실제로 C가 D에 전송해도 되는데 못 하는 상황.
= 동시 전송이 가능함에도 불필요하게 대기하는 비효율.
4IEEE 802.11 무선 LAN 구조
BSS / ESS / AP
BSS(기본 서비스 집합)+DS → ESS(확장 서비스 집합). AP(액세스 포인트)로 DS 연결. 유선 LAN 연결 시 포털(Portal) 사용.
MAC 접근 방식
PCF(비경쟁, AP 중앙 제어) vs DCF(경쟁, CSMA/CA 사용). 실제로 DCF(CSMA/CA)가 주로 사용.
11장 📡 WAN · 교환방식 · 이동통신
1교환 방식 분류 ★★★ (그림 11-3 — 그릴 줄 알아야 함!)
★ 시험 출제 — 직접 그릴 수 있어야 함
그림 11-3 교환 방식의 분류
아래 트리를 종이에 보지 않고 그릴 수 있을 때까지 연습하세요.
교환 방식 ──┬── 회선 교환 (Circuit Switching) │ └── 축적 교환 ──┬── 메시지 교환 (Message Switching) │ └── 패킷 교환 ──┬── 가상 회선 방식 (Virtual Circuit) │ └── 데이터그램 방식 (Datagram)
회선 교환 (Circuit Switching)

1CSMA/CD를 설명하시오.
모범 답안

CSMA/CD는 CS(Carrier Sense, 반송파 감지) + MA(Multiple Access, 다중 접근) + CD(Collision Detection, 충돌 검출)의 유선 LAN 매체 접근 제어 방식이다.

전송 전 채널을 감지하여 비어 있으면 전송하고, 전송 중 다른 장치가 동시 전송하여 충돌이 발생하면 Jam 신호를 보내 모든 장치에 충돌을 알린다. 이후 지수 백오프 알고리즘으로 임의 시간 대기 후 재전송한다. 충돌 재시도 횟수가 15를 초과하면 비정상 종료한다. 이더넷(IEEE 802.3)의 표준이다.

2CSMA/CA를 설명하시오.
모범 답안

CSMA/CA는 무선 LAN(IEEE 802.11)에서 사용하는 충돌 회피(Collision Avoidance) 방식이다. 무선 환경에서는 충돌을 직접 감지할 수 없으므로 사전에 충돌을 피하는 방식을 사용한다.

핵심 메커니즘은 NAV(Network Allocation Vector)이다. 송신 스테이션이 RTS(Request To Send) 프레임에 채널 점유 시간을 포함해 전송하면, 수신 스테이션이 CTS(Clear To Send)를 응답한다. 주변의 모든 스테이션은 CTS를 수신하고 NAV 시간 동안 전송을 하지 않아 충돌을 회피한다. 무선에서는 수신 확인을 위해 ACK가 반드시 필요하다.

3숨겨진 터미널 문제를 설명하시오.
모범 답안

숨겨진 터미널 문제(Hidden Terminal Problem)는 무선 LAN에서 발생하는 문제로, A와 C는 서로 신호 수신 거리 밖에 있어 직접 통신이 불가능하고, B는 A와 C 모두와 통신 가능한 위치에 있는 경우이다.

A가 B로 데이터를 전송 중일 때, C는 이 사실을 알지 못하고 B로 전송을 시도하면 충돌이 발생한다. A의 입장에서 C는 보이지 않는 숨겨진 터미널이다.

해결 방법: RTS/CTS 메커니즘을 사용한다. A가 RTS를 전송하면 B가 CTS를 응답하는데, C도 B의 CTS를 수신할 수 있어 NAV를 설정하고 전송을 중단하여 충돌을 방지한다.

4이동통신 세대별 발전 과정을 서술하시오.
모범 답안

이동통신은 다음과 같이 발전하였다.

1세대(1G, 1981년): 아날로그(AMPS, TACS) 방식으로 10Kbps 이하의 음성 통화만 가능하였다.

2세대(2G, 1991년): 디지털(TDMA, CDMA, GSM) 방식으로 전환되어 14.4~64Kbps의 속도를 제공하며 음성 외에 단문 메시지, 저속 인터넷이 가능해졌다.

3세대(3G, 2000년): IMT-2000 표준(WCDMA, cdma2000)으로 최대 2Mbps를 제공하며, 고속 인터넷·화상통화·국제 로밍이 가능해졌다.

4세대(4G, 2012년): LTE-Advanced(IMT-Advanced)로 100Mbps~1Gbps의 고속 통신을 제공하며 고품질 멀티미디어 서비스가 가능해졌다.

5세대(5G, 2020년): IMT-2020 표준으로 1Gbps 이상을 제공하며 사물인터넷, 홀로그램, 자율주행 등 초연결 서비스를 지원한다.

모범 답안

HDLC 프레임은 플래그 – 주소부 – 제어부 – 정보부 – FCS – 플래그 순으로 구성된다.
플래그(01111110)는 프레임의 시작과 끝을 표시하며, 주소부는 보조국의 주소를 담는다. 제어부에는 순서번호(N(S), N(R))와 P/F 비트가 포함된다. 정보부는 사용자 데이터이며, FCS는 CRC를 이용한 오류 검출 코드이다.

프레임 유형은 I(정보, 데이터 전송), S(감독, 흐름·오류 제어), U(무번호, 링크 관리) 3가지이다. 데이터 투명성을 위해 비트 스터핑(연속된 1이 5개이면 0 삽입)을 사용한다.

6핸드오프 기술을 설명하시오.
모범 답안

핸드오프(Handoff)란 이동국이 현재 서비스 중인 기지국 영역을 벗어나 인접한 기지국으로 이동할 때, 통화를 끊김 없이 유지하기 위해 채널을 새로운 기지국으로 자동 전환하는 기술이다.

핸드오프는 3종류로 분류된다.
① 소프트 핸드오프(Make Before Break): 새 채널을 먼저 연결하고 이전 채널을 나중에 끊는 방식으로, CDMA에서 사용한다.
② 하드 핸드오프(Break Before Make): 현재 채널을 끊고 즉시 다른 채널로 연결하는 방식으로, FDMA·TDMA에서 사용한다.
③ 소프터 핸드오프: 동일 주파수로 동일 셀 내 섹터 간에 발생하는 핸드오프이다.

7전력 제어 기술을 설명하시오.
모범 답안

전력 제어(Power Control)는 기지국에 수신되는 각 이동국의 수신 전력이 동일하도록, 이동국의 송신 전력을 조정하는 기술이다.

거리에 따라 전자파 크기는 1/(10³~10⁵) 정도로 감소한다. 이로 인해 근거리/원거리 문제(Near/far problem)가 발생하는데, 가까이 있는 이동국의 신호가 멀리 있는 이동국의 신호보다 훨씬 강해 멀리 있는 이동국의 복조가 불가능해진다.

이를 해결하기 위해 기지국에 가까운 이동국은 낮은 전력으로, 먼 이동국은 큰 전력으로 송신하도록 기지국이 실시간으로 각 이동국의 송신 전력을 조정한다. CDMA 시스템에서 특히 중요하다.

Q15.서술 슬라이딩 윈도우 방식과 정지-대기 방식을 비교하여 설명하시오.
모범 답안
정지-대기 방식은 한 번에 한 프레임만 전송하고 ACK를 받아야 다음 프레임을 전송하는 방식이다. 구현이 간단하지만 ACK를 기다리는 동안 링크가 낭비되어 전송 효율이 낮다.

슬라이딩 윈도우 방식은 ACK를 받기 전에 윈도우 크기만큼 여러 프레임을 연속 전송할 수 있는 방식이다. TCP에서 사용하며 16비트 윈도우 크기(최대 65,535)를 가진다. 전송 지연이 큰 환경에서 효율적이며 전송 효율이 높다. 수신 장치는 여러 프레임에 대해 하나의 ACK로 응답할 수 있다.
Q16.서술 전력 제어 기술이 이동통신에서 필요한 이유와 동작 방법을 설명하시오.
모범 답안
이동통신에서 전자파의 세기는 거리에 따라 1/(10³~10⁵) 정도로 급격히 감소한다. 이로 인해 근거리/원거리 문제(Near/far problem)가 발생한다. 기지국에 가까이 있는 이동국의 신호가 매우 강해 멀리 있는 이동국의 약한 신호를 가리게 되어, 멀리 있는 이동국의 신호 복조가 불가능해진다.

전력 제어는 이 문제를 해결하기 위해, 기지국에서 수신되는 각 이동국의 수신 전력이 동일하도록 각 이동국의 송신 전력을 실시간으로 조정하는 기술이다. 기지국에 가까운 이동국은 낮은 전력으로, 먼 이동국은 큰 전력으로 송신하도록 기지국이 지시한다. 이를 통해 CDMA의 채널 용량을 최대화할 수 있다.
Q17.서술 오류 검출 방식 4가지를 나열하고, CRC의 동작 원리를 설명하시오.
모범 답안
오류 검출 방식 4가지: ① 패리티 검사 ② 블록 합 검사 ③ CRC(순환 중복 검사) ④ 검사합(Checksum)

CRC(Cyclic Redundancy Check)는 데이터링크 계층에서 가장 많이 사용하는 오류 검출 방법이다.
송신 측: 전송 데이터를 미리 약속된 생성 다항식 G(x)로 나누어 나머지를 구하고, 이를 FCS(Frame Check Sequence)로 데이터 뒤에 붙여 전송한다.
수신 측: 수신된 데이터 전체를 동일한 생성 다항식으로 나누어 나머지가 0이면 오류 없음, 0이 아니면 오류가 발생한 것으로 판단한다. 버스트 오류(연속 오류)도 검출할 수 있다.
