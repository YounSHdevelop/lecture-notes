OSI 참조 모델

네트워크 통신의 국제 표준 — 7계층 구조와 핵심 개념

3

4

📌 핵심 요약

OSI 참조 모델이란?

1984년 ISO에서 이기종 컴퓨터 간 통신을 가능하게 하기 위해 개발한 통신 프로토콜 표준 모델. 통신의 전 과정을 7개 계층으로 분리하여 정의한다.

참조 모델 vs 실제 표준

OSI는 실제 사용되는 프로토콜로 개발되지 못하였지만, 통신 프로토콜을 이해하고 설명하는 기준 모델로 사용된다. 실제적인 표준은 TCP/IP이다.

계층화의 개념

하나의 일을 수행하기 위해 관련 기능들을 모아 그룹화한 구조. 각 계층은 인접한 하위 계층의 서비스를 이용하고, 바로 위 계층에 서비스를 제공한다.

중간 노드의 동작 범위

중간 노드(라우터 등)들은 3계층(네트워크 계층)까지만 동작하며, 종단 간 연결을 위한 상위 계층은 종단 시스템에서만 동작한다.

캡슐화 (Encapsulation)

전송 데이터에 각 계층의 제어 정보(헤더)를 추가하여 다음 계층으로 전달하는 과정. 2계층에서는 오류 제어를 위한 트레일러도 추가한다.

데이터 단위

  • SDU: 상·하위 계층 간 인터페이스를 통해 전달되는 실제 정보
  • PDU: 동일 계층 간에 운반(교환)되는 데이터
    (PDU = SDU + 헤더)

7 응용 계층
Application		 사용자가 네트워크에 접속하는 것을 가능하게 하고, 사용자 인터페이스를 제공. 파일 전송·이메일 같은 종단 사용자 서비스 제공. 대표: NVT, FTAM, X.400, X.500
6 표현 계층
Presentation		 데이터의 표현을 공통된 형식으로 변환, 압축, 암호화 기능 수행. 평문(Plaintext)→암호문(Ciphertext) 변환. 대칭키(DES/AES/SEED), 비대칭키(RSA)
5 세션 계층
Session		 특정 프로세스 간에 세션이라는 연결을 확립하고 유지. 동기점(Synchronization Point) 설정. 반이중(Half-duplex) / 전이중(Full-duplex) 대화 제어
4 전송 계층
Transport		 종단 간 신뢰성 있는 데이터 전송. 종단 간 오류 제어, 흐름 제어
3 네트워크 계층
Network		 호스트 간의 데이터 전송 기능. 데이터의 전송 경로 설정 (라우팅). 폭주 제어(병목현상 방지). 대표 프로토콜: X.25, IP
2 데이터링크 계층
Data Link		 인접 노드 사이의 데이터 전송 기능 수행. 인접 노드 사이의 오류 제어, 흐름 제어, 전송 제어. 트레일러 추가. 대표 프로토콜: HDLC, BSC, PPP, LLC
1 물리 계층
Physical		 물리적인 전송로를 제공. 전송 방식: 신호 형태, 케이블 형태 등 물리적인 전송 매체를 통해 데이터를 목적지까지 전송하기 위해 필요한 기능들을 제어. 대표 프로토콜: ITU-T V.21, EIA RS-232C
🔍 각 계층 상세 설명

1 물리 계층 (Physical Layer)

물리적인 전송 매체를 통해 데이터를 목적지까지 전송하기 위해 필요한 기능들을 제어한다.

기계적 특성

DTE와 DCE 사이의 물리적인 연결에 관한 사항

전기적 특성

신호 형식, 전송 방식, 부호화 방식, 변조 방식, 신호 전압 레벨, 신호 타이밍 등을 규정

기능적 특성

인터페이스의 각 핀이 수행하는 기능을 규정

절차적 특성

데이터를 교환할 때 일련의 절차를 규정

관련된 주요 기능

인터페이스와 전송매체의 물리적 특성 · 비트의 표현 · 데이터 속도 · 비트의 동기화 · 회선 구성 · 접속 형태 · 데이터 전송 방식

대표 프로토콜

• ITU-T V.21: 공중 전화망(PSTN)을 통한 300bps 전이중 모뎀 통신 표준. ITU-T(국제전기통신연합)이 제정
• EIA RS-232C: DTE-DCE 간 직렬 통신 인터페이스 표준(현 TIA-232). DB-9 또는 DB-25 커넥터 사용. 물리적 연결 핀 수·전압·신호 등을 규정

2 데이터링크 계층 (Data Link Layer)

인접하는 두 노드를 직접 연결하는 링크 상에서 프레임 전달을 담당한다. Hop by Hop (Node by Node) 전송.

캡슐화: 네트워크 계층에서 내려온 데이터에 헤더와 트레일러를 덧붙여 프레임을 구성한다.

프레임 구성

네트워크 계층으로부터 받은 비트 스트림을 일정한 길이로 분할

주소 지정

송신자와 수신자의 물리 주소를 프레임 헤더에 추가

흐름 제어

수신 측의 처리 능력을 넘지 않도록 조절
① Stop-and-Wait 방식
② Sliding Window 방식

오류 제어

에러가 발생한 프레임을 검출·복구. 흐름 제어와 결합되어 구현

접근 제어

특정 순간에 어떤 장치가 매체를 사용할지 결정하는 기능

동기화

각 프레임의 시작과 끝을 수신 측에 정확하게 알리는 기능

대표 프로토콜: HDLC, BSC, PPP, LLC

• HDLC (High-Level Data Link Control): ISO 표준 비트 지향 동기 프로토콜. 가장 대표적인 데이터링크 프로토콜
• BSC (Binary Synchronous Communication): IBM이 개발한 문자 지향 동기 프로토콜. HDLC 이전에 광범위하게 사용됨
• PPP (Point-to-Point Protocol): 두 노드 사이 직접 연결(전화선, DSL 등)에 사용. 인증·암호화 기능 포함. 인터넷 접속에 활용
• LLC (Logical Link Control): IEEE 802.2 표준. 데이터링크 계층의 상위 부분으로 상위 계층 프로토콜 다중화 담당

3 네트워크 계층 (Network Layer)

패킷을 발신지로부터 여러 네트워크를 경유하여 목적지까지 전달. 종단 간 전달 (End-to-End Delivery).

캡슐화: 전송 계층에서 받은 데이터를 패킷(데이터 + 헤더)으로 구성하여 데이터링크 계층으로 전달.

패킷 전달

발신지에서 목적지까지 패킷을 전달하는 기능

논리 주소 지정

발신지와 목적지의 논리 주소를 헤더에 추가. 전송 도중 바뀌지 않음

라우팅 (Routing)

데이터가 전송될 가장 적절한 전송 경로를 선택하는 기능

다중화

하나의 데이터 회선으로 동시에 많은 데이터 전송을 수행하는 기능

폭주 제어 (Congestion Control)

병목현상(Bottleneck)을 방지하기 위해 네트워크 내 패킷 수를 제어. 트래픽이 집중될 때 성능 저하를 막는 기능

대표 프로토콜: X.25, IP

• X.25: ITU-T 표준 WAN 패킷 교환 프로토콜. 신뢰성 있는 가상 회선 방식. 오류 제어·흐름 제어·폭주 제어 포함
• IP (Internet Protocol): TCP/IP 인터넷의 핵심 네트워크 계층 프로토콜. 비연결형 패킷 전달

4 전송 계층 (Transport Layer)

전체 메시지를 출발지 응용 프로그램(source process)에서 목적지 응용 프로그램(destination process)까지 전달. 프로세스 대 프로세스 (Process-to-Process) 전달.

헤더 정보

전송 계층 헤더에는 포트 주소(Port Address) 또는 소켓 주소(Socket Address)가 들어있다. 포트 주소로 인해 송신 측 데이터가 수신 측의 해당 프로세스로 정확하게 전달된다.

5 세션 계층 (Session Layer)

특정한 프로세스들 사이에서 세션(가상 연결)을 확립하고 유지하며 동기화하는 기능을 제공한다.

세션 관리

세션의 확립, 유지, 종료를 관리

대화 제어 (Dialog Control)

• 반이중(Half-duplex): 한 번에 한 방향으로만 데이터 전송
• 전이중(Full-duplex): 동시에 양방향 데이터 전송

동기점 (Synchronization Point)

전송 데이터 스트림 내에 체크포인트를 삽입하여, 오류 발생 시 처음부터 재전송하지 않고 마지막 동기점부터 재전송할 수 있도록 한다. 대용량 데이터 전송 시 효율성을 높이는 핵심 기능.
예: 1GB 파일 전송 중 500MB 지점에서 오류 → 처음부터 재전송이 아닌 500MB 동기점부터 재전송

6 표현 계층 (Presentation Layer)

데이터 표현의 차이를 극복한다. 번역(Translation), 암호화, 압축 수행.

예: ASCII 코드 ↔ EBCDIC 코드 변환

손실 압축

JPEG, MPEG, DVI 등

무손실 압축

실행 길이 부호화, 허프만 부호화, LZ 알고리즘 등

대칭키 암호방식

암호화 키 = 복호화 키 (동일 키 사용)
DES, AES, SEED

비대칭키 암호방식

공개 키와 개인 키를 분리하여 사용
RSA

암호화 흐름

평문(Plaintext) → [암호화 알고리즘 + 키] → 암호문(Ciphertext)
암호문(Ciphertext) → [복호화 알고리즘 + 키] → 평문(Plaintext)

대칭키 (비밀키)
  • DES: 56비트 키, 미국 구표준
  • AES: 128/192/256비트 키, 현재 표준
  • SEED: 128비트 키, 한국 표준
비대칭키 (공개키)
  • RSA: 공개키로 암호화, 개인키로 복호화. 키 분배 문제 해결
  • 대칭키보다 느리지만 키 관리가 용이

7 응용 계층 (Application Layer)

응용 프로세스가 네트워크 환경에 접근하는 수단을 제공한다.

사용자가 네트워크에 접속할 수 있도록 하고, 사용자 인터페이스를 제공. 파일 전송·이메일 같은 종단 사용자 서비스를 제공한다.

NVT (Network Virtual Terminal)

서로 다른 터미널 간의 통신을 가능하게 하는 가상 터미널 서비스. TELNET의 기반 개념. 이기종 컴퓨터 간 원격 로그인 지원.

FTAM (File Transfer, Access, Management)

OSI 표준 파일 전송 및 관리 프로토콜. TCP/IP의 FTP에 대응하는 OSI 표준. 파일 전송·접근·관리를 통합 제공.

X.400 (전자 메일)

ITU-T 표준 전자 메일(MHS: Message Handling System) 프로토콜. 인터넷 이메일(SMTP)에 대응하는 OSI 표준.

X.500 (디렉터리 서비스)

ITU-T 표준 디렉터리 서비스. 사용자·자원 정보를 분산 저장·검색. DNS와 LDAP(경량 디렉터리 액세스 프로토콜)의 기반.

📡 계층별 주요 프로토콜
각 계층은 서비스를 구현하기 위해 표준 프로토콜을 사용한다. 계층별 프로토콜을 파악하면 시험 문제를 빠르게 풀 수 있다.

2 데이터링크 LLC Logical Link Control. IEEE 802.2 표준. 데이터링크 계층의 상위 부분으로 상위 계층 프로토콜 다중화
3 네트워크 X.25 ITU-T 표준 WAN 패킷 교환 프로토콜. 신뢰성 있는 가상 회선 방식. 오류 제어·흐름 제어·폭주 제어 포함
3 네트워크 IP Internet Protocol. 인터넷의 핵심 네트워크 계층 프로토콜. 비연결형 패킷 전달
7 응용 NVT Network Virtual Terminal. 이기종 터미널 간 원격 접속을 위한 가상 터미널 표준
7 응용 FTAM File Transfer, Access and Management. OSI 표준 파일 전송·접근·관리 프로토콜
7 응용 X.400 ITU-T 표준 전자 메일(MHS: Message Handling System) 프로토콜
7 응용 X.500 ITU-T 표준 디렉터리 서비스 프로토콜. LDAP(경량 디렉터리 액세스 프로토콜)의 기반
💡 주요 개념

프로토콜 (Protocol)

각 계층의 프로토콜은 동일 계층 사이(peer-to-peer)에 존재한다. 같은 계층끼리 약속된 규칙으로 통신한다.

인터페이스 (Interface)

동일한 장치 내에서 다른 계층과 상호작용하는 것. 같은 장치 안의 인접 계층 간 연결 방식.

서비스 프리미티브
(Service Primitive)

인터페이스를 통해 이루어지는 계층 간 상호 작용을 추상화하여 단순한 모습으로 제공하기 위한 서비스 단위.

SDU vs PDU

  • SDU (Service Data Unit): 상·하위 계층 간 인터페이스를 통해 전달되는 실제 정보
  • PDU (Protocol Data Unit): 동일 계층 간에 운반되는 데이터
    PDU = SDU + 헤더

캡슐화 (Encapsulation)

전송 데이터에 각 계층의 요구 조건과 처리 정보를 포함하는 헤더를 추가하며 하위 계층으로 전달. 2계층은 트레일러도 추가.

역캡슐화 (Decapsulation)

수신 측에서 각 계층이 자신의 헤더를 제거하며 상위 계층으로 데이터를 전달하는 과정. 캡슐화의 반대 과정.

캡슐화 과정 (송신 측)

7 응용 데이터 ← 사용자 데이터 생성
6 표현 H6 데이터
5 세션 H5 H6 데이터
4 전송 H4 … → 세그먼트 (Segment)
3 네트워크 H3 … → 패킷 (Packet)
2 데이터링크 H2 … T2 → 프레임 (Frame) + 트레일러
1 물리 비트(Bit) 스트림으로 전송

⭐ OSI vs TCP/IP 핵심 차이

OSI는 참조 모델(이해·설명 기준), TCP/IP는 실제 표준. OSI가 1984년 ISO에서 먼저 나왔으나, 실제 인터넷은 TCP/IP 기반으로 동작한다.

⭐ 오류 제어 범위 구분

• 데이터링크 계층(2): 인접 노드 사이의 오류 제어, 흐름 제어
• 전송 계층(4): 종단 간(end-to-end)의 오류 제어, 흐름 제어

⭐ 트레일러는 2계층(데이터링크)에서만!

헤더는 모든 계층에서 추가하지만, 트레일러(오류 제어용)는 2계층 데이터링크 계층에서만 추가한다.

⭐ 중간 노드는 3계층까지만 동작

라우터 같은 중간 노드는 1~3계층(물리·데이터링크·네트워크)까지만 처리한다. 4~7계층은 종단 시스템(호스트)에서만 동작한다.

⭐ 물리 계층 프로토콜 — ITU-T V.21 vs EIA RS-232C

• ITU-T V.21: 전화망(PSTN)을 통한 저속(300bps) 모뎀 통신 표준. 신호·변조 방식 규정
• EIA RS-232C: DTE-DCE 간 직렬 인터페이스 케이블·커넥터 표준 (현 TIA-232). 핀 수·전압 레벨 규정

⭐ 데이터링크 계층 프로토콜 비교

• HDLC: 비트 지향 동기 프로토콜 (ISO 표준, 가장 대표적)
• BSC: 문자 지향 동기 프로토콜 (IBM 개발, HDLC 이전)
• PPP: 점대점(Point-to-Point) 연결 전용, 인터넷 접속에 사용
• LLC: IEEE 802.2 표준, 데이터링크 상위 부분

⭐ 네트워크 계층 폭주 제어 (Congestion Control)

네트워크 내 패킷이 너무 많아 병목현상(Bottleneck)이 발생하면 전송 성능이 크게 떨어진다. 네트워크 계층에서 패킷 수를 조절하여 이를 예방한다. X.25와 IP가 이 기능을 담당.

⭐ 세션 계층의 동기점(Synchronization Point)

오류 발생 시 처음부터 재전송하는 비효율을 막기 위해 체크포인트를 삽입한다. 예: 1GB 파일 전송 중 500MB 지점에서 오류 발생 → 처음부터 재전송이 아닌 500MB 동기점부터 재전송.

⭐ 표현 계층 암호화 알고리즘 비교

대칭키: DES(구), AES(현재 표준), SEED(한국 표준) — 속도 빠름, 키 분배 문제 있음
비대칭키: RSA — 속도 느림, 키 분배 문제 없음, 디지털 서명 가능

⭐ 응용 계층 OSI 표준 프로토콜

• NVT: 이기종 터미널 간 원격 접속 (TELNET의 OSI판)
• FTAM: 파일 전송·접근·관리 (FTP의 OSI판)
• X.400: 전자 메일 (SMTP의 OSI판)
• X.500: 디렉터리 서비스 (DNS/LDAP의 기반)

📚 핵심 키워드
OSI Reference Model
OSI 참조 모델
1984년 ISO에서 이기종 컴퓨터 간 통신 표준화를 위해 개발한 7계층 네트워크 구조 모델. 실제 프로토콜은 아니며 참조·이해용 기준 모델.
Protocol
프로토콜
동일 계층(peer-to-peer) 사이에 존재하는 통신 규약. 서로 다른 시스템 간에 데이터를 교환하기 위한 규칙의 집합.
Interface
인터페이스
동일한 장치 내에서 인접한 계층들이 상호 작용하는 방식. 같은 기계 안에서 계층 간 통신 방법.
Service Primitive
서비스 프리미티브
인터페이스를 통한 계층 간 상호 작용을 추상화한 서비스 단위. 계층 간 교환되는 기본적인 서비스 요청/응답 형식.
Encapsulation / Decapsulation
캡슐화 / 역캡슐화
캡슐화: 송신 시 각 계층이 헤더(+트레일러)를 추가하는 과정. 역캡슐화: 수신 시 각 계층이 자신의 헤더를 제거하는 과정.
SDU (Service Data Unit)
서비스 데이터 단위
상위 계층과 하위 계층 간의 인터페이스를 통해 전달되는 실제 정보(페이로드).
PDU (Protocol Data Unit)
프로토콜 데이터 단위
동일 계층 간에 운반(교환)되는 데이터. PDU = SDU + 헤더. 계층마다 다른 이름(패킷, 프레임, 비트 등)으로 불린다.
Header / Trailer
헤더 / 트레일러
헤더: 각 계층이 캡슐화 시 추가하는 제어 정보. 트레일러: 2계층(데이터링크)에서 오류 제어를 위해 데이터 뒤에 추가하는 정보.
Synchronization Point
동기점
세션 계층에서 데이터 스트림 내에 삽입하는 체크포인트. 오류 발생 시 처음부터가 아닌 마지막 동기점부터 재전송하여 효율을 높인다.
Congestion Control
폭주 제어
네트워크 계층에서 패킷 과부하로 인한 병목현상(Bottleneck)을 방지하기 위해 네트워크 내 패킷 수를 조절하는 기능.
Symmetric Key / Asymmetric Key
대칭키 / 비대칭키 암호
대칭키(비밀키): 암호화·복호화에 동일한 키 사용(DES, AES, SEED). 비대칭키(공개키): 공개키로 암호화, 개인키로 복호화(RSA). 표현 계층에서 수행.
BSC (Binary Synchronous Communication)
이진 동기 통신
IBM이 개발한 문자 지향 동기 데이터링크 프로토콜. HDLC 이전에 광범위하게 사용되었다. 데이터링크 계층.
X.25
X.25 프로토콜
ITU-T 표준 WAN 패킷 교환 네트워크 계층 프로토콜. 신뢰성 있는 가상 회선 방식으로 오류 제어와 흐름 제어를 포함한다.
NVT (Network Virtual Terminal)
네트워크 가상 터미널
이기종 터미널 간 원격 접속을 위한 응용 계층 표준. 서로 다른 컴퓨터 터미널이 통신할 수 있도록 공통 가상 터미널을 정의한다.
Half-duplex / Full-duplex
반이중 / 전이중
세션 계층의 대화 제어 방식. 반이중: 한 번에 한 방향으로만 전송. 전이중: 동시에 양방향으로 전송.

Q12. 표현 계층에서 사용하는 손실 압축 포맷이 아닌 것은?

Q14. [단답형] 데이터링크 계층의 대표적인 프로토콜은?
Q15. 물리 계층 프로토콜에 해당하지 않는 것은?
BSC(Binary Synchronous Communication)는 데이터링크 계층 프로토콜입니다. ITU-T V.21과 EIA RS-232C는 물리 계층 표준입니다.
Q16. 네트워크 계층에서 병목현상(Bottleneck)을 방지하기 위해 패킷 수를 조절하는 기능은?
폭주 제어(Congestion Control)는 네트워크 내 패킷이 과부하되어 병목현상이 발생하는 것을 방지합니다. 흐름 제어는 수신 측의 처리 속도를 넘지 않도록 하는 것으로 다릅니다.
Q17. 세션 계층에서 오류 발생 시 처음부터 재전송하지 않고 특정 지점부터 재전송할 수 있도록 하는 기능은?
동기점(Synchronization Point)은 데이터 전송 중 체크포인트를 삽입하여 오류 발생 시 마지막 동기점부터 재전송하는 기능입니다. 대용량 파일 전송 시 매우 효율적입니다.
Q18. 대칭키 암호화 알고리즘이 아닌 것은?
RSA는 비대칭키(공개키) 암호화 알고리즘입니다. DES, AES, SEED는 모두 대칭키 암호화 알고리즘입니다. SEED는 한국에서 개발한 128비트 대칭키 알고리즘입니다.
Q19. [단답형] ITU-T 표준 WAN 패킷 교환 네트워크 계층 프로토콜은? (X.__형태로 입력)
Q20. 응용 계층의 프로토콜과 그 설명이 올바르게 연결된 것은?
X.400은 ITU-T 표준 전자 메일(MHS) 프로토콜입니다. NVT는 가상 터미널, FTAM은 파일 전송, X.500은 디렉터리 서비스입니다.
Q21. 세션 계층의 대화 제어(Dialog Control)에서 한 번에 한 방향으로만 데이터를 전송하는 방식은?
반이중(Half-duplex)은 한 번에 한 방향으로만 데이터를 전송합니다. 전이중(Full-duplex)은 동시에 양방향으로 데이터를 전송합니다.
