학습 목표

① 상속의 개념

extends 키워드로 부모 클래스를 상속받고 super를 통해 부모의 생성자와 멤버에 접근할 수 있다.

② 메서드 오버라이딩

부모 메서드를 자식 클래스에서 재정의하고 @Override 어노테이션을 통해 컴파일 오류를 방지한다.

③ 업캐스팅 / 다운캐스팅

자식 객체를 부모 타입으로 변환(자동), 부모 타입을 자식 타입으로 변환(명시적)하는 방법을 이해한다.

④ 동적 바인딩 & 다형성

업캐스팅된 변수로 메서드를 호출할 때 실제 객체의 오버라이딩된 메서드가 실행되는 원리를 이해한다.

⑤ 추상 클래스

abstract 클래스와 메서드를 선언하고, 자식 클래스에서 구현을 강제하는 구조를 설계할 수 있다.

⑥ 인터페이스

interface와 implements를 이용해 다중 구현, default·static 메서드를 활용할 수 있다.

핵심 요약

🔑 상속 기본 문법

class Donut {             // 부모 클래스
    String name;
    int price;
    void show() { ... }
}

class ChocoDonut extends Donut {   // 자식
    String topping;

    void addTopping() { ... }
}

자식 클래스는 부모의 name, price, show()를 그대로 사용할 수 있다.

🔑 super 사용

class ChocoDonut extends Donut {
    ChocoDonut() {
        super();  // 부모 생성자 호출 (첫 줄!)
    }

    void show() {
        System.out.println(super.name);  // 부모 필드
        super.show();  // 부모 메서드
    }
}

🔑 업캐스팅 / 다운캐스팅

// 업캐스팅 (자동)
Donut d = new ChocoDonut();

// 다운캐스팅 (명시적)
if (d instanceof ChocoDonut) {
    ChocoDonut choco = (ChocoDonut) d;
    choco.addTopping();
}

// instanceof 없이 다운캐스팅 → ClassCastException!

🔑 추상 클래스 vs 인터페이스

// 추상 클래스
abstract class Donut {
    abstract void show();  // 구현 강제
    void common() { ... } // 일반 메서드 OK
}

// 인터페이스
interface Sellable {
    void pack();
    default void pay() { ... }  // Java 8+
}

class C extends Donut
         implements Sellable, Payable { }
Section 01 — 상속의 개념과 사용 방법

1. 상속이란?

상속(Inheritance)이란 이미 만들어진 클래스(부모 클래스)가 가진 속성과 기능을 새로운 클래스(자식 클래스)가 그대로 사용할 수 있도록 하는 개념이다. 자식 클래스는 부모 기능을 물려받으므로 중복 코드를 줄이고 코드의 재사용성을 높이는 역할을 한다. 자바에서 상속은 extends 키워드를 사용한다.

⚠️ 자바 상속의 중요 특징

  • 자바는 단일 상속만 지원한다 — 부모 클래스를 한 번에 하나만 상속받을 수 있다
  • 자바의 모든 클래스는 최상위 Object 클래스를 자동으로 상속한다
  • 인터페이스는 다중 구현 가능 (상속과 다름)

2. 접근 제한자와 상속 시험 필수

구분같은 클래스같은 패키지다른 패키지
(상속받은 클래스)		다른 패키지
(관계없는 클래스)
public○○○○
protected○○○✕
default (생략)○○✕✕
private○✕✕✕

💡 protected의 핵심

다른 패키지에 있더라도 상속받은 자식 클래스라면 접근 가능하다. 부모 클래스에서 자식에게만 허용하고 싶은 멤버에 사용한다.

3. super와 생성자 호출 시험 필수

super의 세 가지 용도

  • super() — 부모 클래스의 생성자 호출
  • super.변수 — 부모 클래스의 필드 참조
  • super.메서드() — 부모 클래스의 메서드 호출

생성자 호출 순서

부모 생성자
→
자식 생성자

🚨 super() 작성 규칙

  • 생성자의 첫 번째 줄에 위치해야 한다
  • super()와 this()를 동시에 사용할 수 없다
  • 생성자에서 super()를 생략하면 컴파일러가 자동으로 super() 삽입
  • 부모 클래스에 기본 생성자가 없으면 반드시 명시적으로 super(인자) 호출
class Donut {
    String name;
    Donut(String name) {
        this.name = name;
    }
}

class ChocoDonut extends Donut {
    String topping;
    ChocoDonut(String name, String topping) {
        super(name);      // ← 반드시 첫 줄, 부모 생성자 호출
        this.topping = topping;
    }
}
메서드 오버라이딩 (Method Overriding)

오버라이딩 규칙 시험 필수

✅ 오버라이딩 조건 (모두 같아야 함)

  • 메서드 이름이 같아야 함
  • 매개변수 타입·개수·순서가 같아야 함
  • 반환형이 같거나 자식 타입(공변 반환)이어야 함

🚨 오버라이딩 불가 조건

  • private 메서드
  • static 메서드
  • final 메서드
  • 접근 제한자를 더 좁게 변경 불가
    (public → protected 불가)
class Donut {
    void show() {
        System.out.println("이것은 기본 도넛이다.");
    }
}

class ChocoDonut extends Donut {
    @Override
    void show() {  // 오버라이딩
        // super.show(); 호출 가능 → 부모 메서드 포함 실행
        System.out.println("이것은 달콤한 초코 도넛이다.");
    }
}

💡 오버로딩 vs 오버라이딩 비교

구분오버로딩(Overloading)오버라이딩(Overriding)
적용 대상같은 클래스 내부부모-자식 클래스 간
메서드 이름같아야 함같아야 함
매개변수달라야 함같아야 함
반환형상관없음같거나 좁아야 함
접근 제한자상관없음더 좁게 변경 불가

final과 상속 제한

final 변수

한 번 초기화 후 값 변경 불가
final int MAX = 10;

final 메서드

자식 클래스에서 오버라이딩 불가
final void recipe() { }

final 클래스

다른 클래스가 상속 불가
final class Donut { }

Section 02 — 업캐스팅 & 다운캐스팅 시험 필수

업캐스팅 (Upcasting)

자식 객체를 부모 타입으로 변환 — 자동

ChocoDonut choco = new ChocoDonut();
Donut d = choco;  // 업캐스팅 (자동)

// 업캐스팅 후에는 Donut에 정의된
// 멤버에만 접근 가능!
d.show();      // OK
d.addTopping(); // 오류! Donut에 없는 메서드

업캐스팅 후 d.show()를 호출하면 동적 바인딩에 의해 실제 객체(ChocoDonut)의 오버라이딩된 show()가 실행된다.

다운캐스팅 (Downcasting)

부모 타입을 자식 타입으로 변환 — 명시적 (강제)

Donut d = new ChocoDonut();  // 업캐스팅

// instanceof로 반드시 확인 후 다운캐스팅
if (d instanceof ChocoDonut) {
    ChocoDonut choco = (ChocoDonut) d;
    choco.addTopping(); // 자식 메서드 사용 가능
}

// instanceof 확인 없이 잘못된 캐스팅
// → ClassCastException 런타임 오류!

🚨 ClassCastException

instanceof로 타입을 먼저 확인하지 않으면 런타임에 ClassCastException이 발생한다.

instanceof 연산자

Donut d1 = new Donut();
Donut d2 = new ChocoDonut();
Donut d3 = new LemonDonut();

System.out.println(d1 instanceof Donut);       // true
System.out.println(d2 instanceof Donut);       // true  (자식도 부모 instanceof true)
System.out.println(d2 instanceof ChocoDonut);  // true
System.out.println(d3 instanceof ChocoDonut);  // false
System.out.println(d2 instanceof LemonDonut);  // false

자식 클래스의 인스턴스는 부모 클래스의 instanceof도 true를 반환한다. 다운캐스팅하기 전 반드시 instanceof로 확인하는 것이 좋다.

동적 바인딩 & 다형성 (Polymorphism)

1. 동적 바인딩 (Dynamic Binding) 시험 필수

업캐스팅된 부모 타입 변수로 메서드를 호출할 때, 실제 생성된 객체(자식)의 오버라이딩된 메서드가 실행된다. 이것을 동적 바인딩(dynamic binding)이라 한다. 컴파일 시간이 아닌 실행 시간에 메서드가 결정된다. 

class Donut { void show() { System.out.println("기본 도넛"); } }
class ChocoDonut extends Donut { @Override void show() { System.out.println("초코 도넛"); } }
class LemonDonut extends Donut { @Override void show() { System.out.println("레몬 도넛"); } }

Donut d1 = new Donut();       // 기본 도넛
Donut d2 = new ChocoDonut();  // 초코 도넛  ← 동적 바인딩!
Donut d3 = new LemonDonut();  // 레몬 도넛  ← 동적 바인딩!
d1.show(); d2.show(); d3.show();

2. 다형성 활용 — 배열로 다양한 객체 관리

Donut[] donuts = {
    new Donut(),
    new ChocoDonut(),
    new LemonDonut()
};

for (Donut d : donuts) {
    d.show();  // 각 객체의 실제 오버라이딩된 메서드 실행 (동적 바인딩)
}

💡 다형성의 3가지 요소

  • 상속 — 부모-자식 관계
  • 메서드 오버라이딩 — 자식이 부모 메서드를 재정의
  • 업캐스팅 — 부모 타입 변수로 자식 객체 참조
추상 클래스 (Abstract Class)

추상 클래스의 특징 시험 필수

추상 클래스란?

  • abstract 키워드 사용
  • 직접 객체 생성 불가 (new Donut() → 오류)
  • 추상 메서드 + 일반 메서드 모두 가질 수 있음
  • 생성자, 필드 선언 가능
  • 자식 클래스에서 추상 메서드 반드시 구현해야 함

추상 메서드란?

  • 메서드 이름만 선언, 구현부 없음
  • abstract void show();
  • 중괄호 없이 세미콜론으로 끝남
  • 자식 클래스가 구현을 제공해야 함
  • private, static, final과 함께 사용 불가
abstract class Donut {        // 추상 클래스
    String name;
    int price;

    void setPrice(int price) {   // 일반 메서드 — 자식이 그대로 사용
        this.price = price;
    }

    abstract void show();        // 추상 메서드 — 자식이 반드시 구현
}

class ChocoDonut extends Donut {
    @Override
    void show() {  // 추상 메서드 구현
        System.out.println("맛있습니다. 가격: " + price + "원");
    }
}

// Donut d = new Donut(); → 오류! 추상 클래스는 직접 생성 불가
Donut d = new ChocoDonut();   // OK — 업캐스팅
인터페이스 (Interface)

인터페이스의 특징

인터페이스란?

  • interface 키워드로 선언
  • 모든 메서드는 기본적으로 public abstract
  • 모든 필드는 public static final
  • 직접 객체 생성 불가
  • 클래스는 여러 인터페이스 동시 구현 가능 (다중 구현)
  • 인터페이스끼리 extends로 상속 가능

Java 8 이후 추가 기능

  • default 메서드 — 인터페이스 안에 구현 코드 작성 가능
  • static 메서드 — 인터페이스 이름으로 직접 호출 가능
  • 구현 클래스에서 default 메서드를 오버라이딩할 수 있음
interface Sellable {
    void pack();                 // 추상 메서드 (public abstract 생략)
    default void pay() {         // default 메서드 (Java 8+)
        System.out.println("결제 완료");
    }
    static void printBanner() {  // static 메서드 (Java 8+)
        System.out.println("도넛 주문 시스템");
    }
}

interface Payable {
    void pay();
}

// 다중 구현
class ChocoDonut implements Sellable, Payable {
    @Override
    public void pack() { System.out.println("초코 도넛 포장 완료"); }
    @Override
    public void pay() { System.out.println("초코 도넛 결제 완료"); }
}

// 인터페이스 타입 변수 선언 가능
Sellable donut = new ChocoDonut();
donut.pack();
Sellable.printBanner();  // static 메서드는 인터페이스 이름으로 호출

핵심 캐치 — 시험 포인트
POINT 01

super()는 반드시 첫 줄

자식 생성자에서 super()를 두 번째 줄 이후에 작성하면 컴파일 오류. 첫 줄에만 위치할 수 있다.

POINT 02

업캐스팅 후 자식 멤버 접근 불가

업캐스팅 후 부모 타입 변수로는 부모 클래스에 선언된 멤버만 접근 가능. 자식 전용 메서드는 다운캐스팅 후 사용.

POINT 03

동적 바인딩 — 실제 객체의 메서드 실행

Donut d = new ChocoDonut()일 때 d.show()는 Donut의 show()가 아닌 ChocoDonut의 show()가 실행된다.

POINT 04

instanceof 후 다운캐스팅

다운캐스팅 전 반드시 instanceof로 타입을 확인해야 ClassCastException을 방지할 수 있다.

POINT 05

추상 클래스 직접 생성 불가

abstract class는 new로 직접 생성할 수 없다. 반드시 자식 클래스를 통해서만 인스턴스 생성 가능.

POINT 06

인터페이스 — 다중 구현 가능

클래스는 단일 상속만 가능하지만, 인터페이스는 여러 개를 동시에 implements 할 수 있다. 단, 모든 메서드를 구현해야 한다.

POINT 07

@Override 어노테이션의 역할

컴파일러가 오버라이딩 규칙(이름, 매개변수)이 맞는지 검사. 오버라이딩이 아니면 컴파일 오류 발생 → 오타 방지.

POINT 08

오버라이딩 접근 제한자 규칙

오버라이딩 시 부모보다 좁은 접근 제한자로 변경 불가. public 메서드를 protected로 오버라이딩하면 컴파일 오류.

부모 클래스의 생성자(super()), 필드(super.x), 메서드(super.m())를 참조
@Override
오버라이딩 어노테이션
메서드 오버라이딩임을 명시. 컴파일러가 오버라이딩 규칙 위반 여부를 검사
instanceof
타입 확인 연산자
객체가 특정 클래스/인터페이스의 인스턴스인지 확인. 다운캐스팅 전 사용 권장
abstract
추상 클래스/메서드
구현 없이 선언만 하는 메서드 또는 그것을 포함하는 클래스. 자식 클래스가 구현 강제
interface
인터페이스
추상 메서드와 상수만을 갖는 타입. implements 키워드로 구현하며 다중 구현 가능
implements
인터페이스 구현
클래스가 인터페이스를 구현할 때 사용. 여러 인터페이스를 쉼표로 나열 가능
dynamic binding
동적 바인딩
업캐스팅된 변수로 메서드 호출 시 실행 시간에 실제 객체의 오버라이딩된 메서드가 결정됨
Upcasting
업캐스팅
자식 타입을 부모 타입 변수에 대입. 자동 형 변환. 부모 멤버에만 접근 가능
Downcasting
다운캐스팅
부모 타입을 자식 타입으로 명시적 형 변환. instanceof 확인 필수. ClassCastException 주의
default method
디폴트 메서드 (Java 8+)
인터페이스 안에 구현 코드를 포함한 메서드. default 키워드 사용. 구현 클래스에서 오버라이딩 가능
Polymorphism
다형성
하나의 부모 타입 변수로 여러 자식 객체를 다루는 것. 상속 + 오버라이딩 + 업캐스팅의 결합
연습문제 — 프로그래밍 중심
PROGRAMMING ① — 코드 추적
다음 코드의 실행 결과로 올바른 것은? 
class A { void print() { System.out.println("A"); } }
class B extends A { @Override void print() { System.out.println("B"); } }
class C extends A { @Override void print() { System.out.println("C"); } }

A[] arr = { new A(), new B(), new C() };
for (A obj : arr) obj.print();
정답: ③ A B C
동적 바인딩(dynamic binding)에 의해 실제 생성된 객체의 오버라이딩된 메서드가 실행된다. arr[0]은 A → "A", arr[1]은 B → "B", arr[2]은 C → "C".
PROGRAMMING ② — 코드 추적
다음 코드의 출력 결과로 올바른 것은? 
class Parent {
    String name = "부모";
    Parent() { System.out.println("Parent 생성자"); }
}
class Child extends Parent {
    String name = "자식";
    Child() {
        // super()가 자동 삽입됨
        System.out.println("Child 생성자");
    }
}
new Child();
정답: ② Parent 생성자 → Child 생성자
자식 생성자에서 super()가 자동 삽입되므로 부모 생성자가 먼저 실행된다. 생성자 호출 순서는 항상 부모 → 자식.
PROGRAMMING ③ — 오류 찾기
다음 코드에서 컴파일 오류가 발생하는 줄 번호는? 
01  abstract class Shape {
02      abstract double area();
03  }
04  class Circle extends Shape {
05      double radius;
06      double area() { return 3.14 * radius * radius; }
07  }
08  public class Test {
09      public static void main(String[] args) {
10          Shape s1 = new Circle();   // 업캐스팅
11          Shape s2 = new Shape();    // ?
12      }
13  }
정답: ③ 11번 줄
추상 클래스(abstract class)는 직접 객체를 생성할 수 없다. new Shape()는 컴파일 오류. 10번 줄의 업캐스팅은 정상이다.
PROGRAMMING ④ — instanceof 결과
다음 코드에서 출력 결과가 true가 아닌 것은? 
class Animal { }
class Dog extends Animal { }
class GoldenRetriever extends Dog { }

GoldenRetriever g = new GoldenRetriever();
정답: ④ g instanceof String
상속 계층상 GoldenRetriever는 Dog, Animal, Object의 자식이므로 ①②③ 모두 true. String과는 무관하므로 false. 단, 컴파일러가 관계없음을 알면 컴파일 오류를 발생시키기도 한다.
PROGRAMMING ⑤ — 코드 완성 (상속 + super)
아래 빈칸을 채워 올바른 상속 구조를 완성하시오.
Vehicle에는 String brand와 void info()가 있다. Car는 Vehicle을 상속받고, int speed 필드를 추가하며, 생성자에서 super(brand)를 호출한다. 
class Vehicle {
    String brand;
    Vehicle(String brand) {
        this.brand = brand;
    }
    void info() {
        System.out.println("브랜드: " + brand);
    }
}

class Car ________ Vehicle {   // ① 상속 키워드
    int speed;
    Car(String brand, int speed) {
        ________(brand);           // ② 부모 생성자 호출
        this.speed = speed;
    }
    @Override
    void info() {
        ________.info();           // ③ 부모 메서드 호출
        System.out.println("속도: " + speed);
    }
}
정답:
① extends
② super(brand) — 부모 생성자 호출, 반드시 생성자 첫 줄
③ super.info() — 부모의 info() 메서드 호출

완성 코드: class Car extends Vehicle / super(brand); / super.info();
PROGRAMMING ⑥ — 추상 클래스 구현
다음 추상 클래스 Animal을 상속받는 Dog 클래스를 완성하시오. Dog의 speak()는 "멍멍!"을 출력하고, move()는 "네 발로 달린다"를 출력해야 한다. 
abstract class Animal {
    String name;
    Animal(String name) { this.name = name; }
    abstract void speak();
    abstract void move();
}

// Dog 클래스를 직접 작성해보세요
모범 답안: 
class Dog extends Animal {
    Dog(String name) {
        super(name);  // 부모 생성자 호출 (첫 줄!)
    }

    @Override
    void speak() {
        System.out.println(name + ": 멍멍!");
    }

    @Override
    void move() {
        System.out.println(name + ": 네 발로 달린다");
    }
}
핵심 포인트: 추상 메서드 2개를 모두 @Override로 구현해야 컴파일 오류가 없다.
PROGRAMMING ⑦ — 인터페이스 + 다형성
아래 코드에서 실행 결과를 작성하고, 동작 원리를 설명하시오. 
interface Printable {
    void print();
}

class Doc implements Printable {
    @Override
    public void print() { System.out.println("문서 출력"); }
}

class Photo implements Printable {
    @Override
    public void print() { System.out.println("사진 출력"); }
}

Printable[] items = { new Doc(), new Photo(), new Doc() };
for (Printable p : items) p.print();
실행 결과:
문서 출력
사진 출력
문서 출력

동작 원리 (동적 바인딩 + 다형성):
Printable 인터페이스 타입 배열에 여러 구현 객체를 담는다. 반복문에서 p.print()를 호출하면 컴파일 시가 아닌 실행 시에 실제 객체(Doc/Photo)의 오버라이딩된 print()가 결정된다. 이것이 동적 바인딩이고, 다형성(Polymorphism)의 핵심이다.
PROGRAMMING ⑧ — 종합: 상속 + 인터페이스
다음 조건으로 클래스를 설계하고 main에서 실행 결과를 예측하시오.
- abstract class Product: String name 필드, 추상 메서드 void show()
- interface Deliverable: void ship(), void confirm()
- class Book extends Product implements Deliverable: show()는 "책: {name}", ship()은 "책 배송 중", confirm()은 "책 수령 완료"
// 이 코드의 출력 결과를 예측하세요
Product p = new Book("자바프로그래밍");
p.show();

Deliverable d = (Deliverable) p;
d.ship();
d.confirm();
전체 구조 (Product + Deliverable + Book) 
// ① 추상 클래스 — 접근 제한자 없음(package-private)
abstract class Product {
    String name;
    Product(String name) { this.name = name; }
    abstract void show();         // package-private
}

// ② 인터페이스 — 모든 메서드는 암묵적으로 public abstract
interface Deliverable {
    void ship();                  // 실제론 public abstract void ship()
    void confirm();               // 실제론 public abstract void confirm()
}

// ③ Book — 출처에 따라 구현 방식이 다르다!
class Book extends Product implements Deliverable {
    Book(String name) {
        super(name);              // Product(String) 생성자 호출
    }

    // 추상 클래스에서 상속 → 원래 package-private이므로 public 없어도 OK
    @Override
    void show() {
        System.out.println("책: " + name);
    }

    // 인터페이스에서 구현 → 원래 public이므로 반드시 public 붙여야 함
    // (public → package-private 으로 좁히면 컴파일 오류!)
    @Override
    public void ship() {
        System.out.println(name + " 책 배송 중");
    }

    @Override
    public void confirm() {
        System.out.println(name + " 책 수령 완료");
    }
}
핵심 차이 정리
추상 클래스 메서드: 선언된 접근 제한자 그대로 구현 → show()는 public 불필요
인터페이스 메서드: 항상 public abstract가 기본값 → ship(), confirm()은 public 필수
실행 결과:
책: 자바프로그래밍
자바프로그래밍 책 배송 중
자바프로그래밍 책 수령 완료

추가 포인트: p는 Product 타입이므로 show()만 호출 가능. ship(), confirm()을 호출하려면 Deliverable 타입으로 캐스팅 필요.
