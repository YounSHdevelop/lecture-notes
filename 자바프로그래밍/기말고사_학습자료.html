스트림은 단방향 — 하나의 스트림으로 입력과 출력 동시 불가!
FileReader — 파일 읽기
try (FileReader fr = new FileReader("data.txt")) { int ch; // read()는 int 반환, EOF = -1 while ((ch = fr.read()) != -1) { System.out.print((char) ch); // char로 형변환 } } catch (IOException e) { e.printStackTrace(); }
read()는 int 반환 — EOF(파일 끝) 도달 시 -1 반환 (0이 아님!)
FileWriter — 파일 쓰기
덮어쓰기 (기본)
try (FileWriter fw = new FileWriter("data.txt")) { fw.write("내용"); } catch (IOException e) { }

기존 파일 있으면 내용 전부 삭제 후 덮어씀

이어쓰기 (append)
try (FileWriter fw = new FileWriter("data.txt", true)) { fw.write("추가 내용"); } catch (IOException e) { }

🔑 핵심 키워드 전체 정리
Inheritance
상속
extends 키워드로 부모 클래스의 속성과 메서드를 물려받는 것. 단일 상속만 가능.
Overriding
메서드 재정의
자식 클래스에서 부모 메서드를 같은 시그니처로 재정의. @Override 권장.
Upcasting
업캐스팅
자식 객체를 부모 타입 변수에 대입. 자동 변환. 자식 고유 메서드 접근 불가.
Downcasting
다운캐스팅
부모 타입을 자식 타입으로 명시적 형변환. instanceof로 확인 후 사용.
Dynamic Binding
동적 바인딩
런타임에 실제 객체의 메서드가 호출되는 것. 다형성의 핵심 원리.
Polymorphism
다형성
하나의 타입으로 여러 형태의 객체를 다루는 것. 업캐스팅+동적 바인딩.
Abstract Class
추상 클래스
abstract 키워드. 직접 인스턴스화 불가. 일반+추상 메서드 혼합 가능.
Interface
인터페이스
다중 implements 가능. 필드=상수, 메서드=추상. 생성자 없음.
Immutable
불변 객체
String이 대표적. 한 번 생성하면 내용 변경 불가. 수정 시 새 객체 생성.
Auto-boxing
오토박싱
기본형 → 래퍼 클래스 자동 변환. 반대는 언박싱(Unboxing).
Generic
제네릭
컴파일 시점 타입 체크. <T> 타입 파라미터. 기본형 사용 불가.
Collection
컬렉션
List(순서O 중복O), Set(순서X 중복X), Map(키-값 쌍) 인터페이스 계층.
Lambda
람다 표현식
(매개변수) → 실행문. 함수형 인터페이스(추상메서드 1개)에서만 사용.
Stream
입출력 스트림
단방향 데이터 통로. 바이트(1B)/문자(2B) 스트림으로 구분.
try-with-resources
자원 자동 반납
Java 7~. 블록 종료 시 자동 close(). AutoCloseable 구현 필수.
EOF
파일 끝
End Of File. read() 메서드가 파일 끝에 도달하면 -1을 반환.

Q16장 — 객관식
다음 코드의 출력 결과로 올바른 것은?
class A { int x = 10; void show() { System.out.println("A:"+x); } } class B extends A { int x = 20; void show() { System.out.println("B:"+x); } } A obj = new B(); obj.show(); System.out.println(obj.x);
① B:20   20
② B:20   10
③ A:10   10
④ A:10   20
✅ 정답: ②
obj.show() → 메서드는 동적 바인딩 → B의 show() → B:20
obj.x → 필드는 동적 바인딩 없음 → 참조 변수 타입 A 기준 → 10
Q26장 — 객관식
다음 중 인터페이스에 대한 설명으로 틀린 것은?
① 인터페이스의 필드는 자동으로 public static final이 붙는다.
② 하나의 클래스가 여러 인터페이스를 동시에 구현할 수 있다.
③ 인터페이스는 생성자를 가질 수 있다.
④ 인터페이스의 메서드는 자동으로 public abstract가 붙는다.
✅ 정답: ③
인터페이스는 생성자 없음 — 객체 생성 자체가 불가능하므로.
