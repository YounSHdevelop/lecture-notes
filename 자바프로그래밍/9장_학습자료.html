입출력 스트림 개요

1. 스트림(Stream)이란

자바에서 외부(파일·콘솔·네트워크)와 데이터를 주고받는 단방향 데이터 통로입니다. 모든 입출력 처리는 java.io 패키지의 스트림 클래스를 통해 이루어집니다.

2. 스트림 분류

🔢 바이트 스트림

  • 1바이트 단위 처리
  • 이미지, 동영상, 바이너리 파일
  • InputStream / OutputStream
  • FileInputStream / FileOutputStream

🔤 문자 스트림

  • 2바이트(유니코드) 단위 처리
  • 텍스트 파일, 한글 등 다국어 처리
  • Reader / Writer
  • FileReader / FileWriter 주요 사용

파일 입출력 — 읽기 (FileReader)

1. 파일 경로 지정 방법 시험 필수

상대
menu.txt — 현재 작업 디렉터리의 menu.txt
data/menu.txt — 현재 디렉터리 안 data 폴더의 menu.txt
../menu.txt — 상위 디렉터리의 menu.txt

현재 작업 디렉터리(프로젝트 루트) 기준. IDE에서는 프로젝트 폴더.

절대
Windows: C:\menu.txt 또는 C:\\menu.txt
Unix/Linux: /home/username/menu.txt

파일 시스템 최상위(루트)부터 전체 경로. 이식성이 낮으므로 상대 경로 권장.

💡 윈도우 경로 주의: \는 이스케이프 문자이므로 C:\menu.txt가 아닌 C:\\menu.txt 또는 C:/menu.txt로 작성해야 합니다.

2. 한 문자씩 읽기 (FileReader) 시험 필수

import java.io.FileReader; import java.io.IOException; public class FileReadExample { public static void main(String[] args) throws IOException { FileReader fin = new FileReader("menu.txt"); // 파일 연결 int ch; while ((ch = fin.read()) != -1) { // -1이면 파일 끝 System.out.print((char) ch); // int → char 형변환 } fin.close(); // 스트림 반드시 닫기 } }
패턴 암기: while ((ch = fin.read()) != -1)
read()가 반환하는 int 값을 ch에 저장하고, -1이 아닌 동안 반복합니다. 출력 시에는 (char) ch로 형변환이 필요합니다.

3. 여러 문자 한 번에 읽기 (char 배열)

try (FileReader fin = new FileReader("menu.txt")) { char[] cbuf = new char[10]; // 10크기의 char 배열 int count; while ((count = fin.read(cbuf)) != -1) { for (int i = 0; i < count; i++) { System.out.print(cbuf[i]); // 읽은 만큼만 출력 } } } catch (IOException e) { System.err.println("오류 발생: " + e.getMessage()); }

read(cbuf)는 배열을 채우며 읽고 실제로 읽은 문자 수를 반환합니다. 파일 마지막에서 배열이 덜 채워질 수 있으므로 i < count로 읽은 만큼만 처리해야 합니다.

✍️
파일 입출력 — 쓰기 (FileWriter)

1. 파일에 문자열 쓰기 시험 필수

import java.io.FileWriter; import java.io.IOException; try (FileWriter fout = new FileWriter("new_menu.txt")) { fout.write("4. 크림 도넛\n"); // \n으로 줄바꿈 fout.write("5. 딸기 도넛\n"); fout.write("6. 생딸기 도넛\n"); System.out.println("파일 쓰기 완료!"); } catch (IOException e) { System.err.println("오류 발생: " + e.getMessage()); }
기본 동작: 파일이 없으면 새로 생성. 파일이 이미 있으면 기존 내용 전부 삭제 후 덮어씁니다.

2. 파일 이어쓰기 (append 옵션) 시험 필수

❌ FileWriter("파일", false)

  • 기존 내용 전부 삭제
  • 새 내용으로 덮어씀
  • 기본값(생략 시)

✅ FileWriter("파일", true)

  • 기존 내용 유지
  • 파일 끝에 이어서 추가
  • append = true
// menu.txt 내용: 1.기본도넛 2.초코도넛 3.레몬도넛 // true = 이어쓰기 (append) try (FileReader fin = new FileReader("menu.txt"); FileWriter fout = new FileWriter("new_menu.txt", true)) { int ch; while ((ch = fin.read()) != -1) { fout.write(ch); // menu.txt 내용 복사 } System.out.println("파일 이어쓰기 완료!"); }
⚠️
파일 입출력 예외 처리

1. try-catch 방식 (전통적)

import java.io.FileReader; import java.io.IOException; FileReader fin = null; try { fin = new FileReader("menu.txt"); int ch; while ((ch = fin.read()) != -1) { System.out.print((char) ch); } } catch (IOException e) { System.err.println("오류 발생: " + e.getMessage()); // 오류 메시지 e.printStackTrace(); // 오류 상세 추적 } finally { if (fin != null) { try { fin.close(); } catch (IOException e) {} } }

finally 블록은 예외 발생 여부와 관계없이 항상 실행됩니다. close()를 여기서 호출하여 자원을 반환합니다.

2. try-with-resources 방식 (권장) 시험 필수

// try () 안에 스트림 선언 → 블록 종료 시 자동으로 close() 호출 try (FileReader fin = new FileReader("menu.txt")) { int ch; while ((ch = fin.read()) != -1) { System.out.print((char) ch); } } catch (IOException e) { System.err.println("오류 발생: " + e.getMessage()); }
✅ try-with-resources 장점: finally 블록 없이도 자동으로 close()를 호출합니다. 스트림을 여러 개 열 때도 세미콜론(;)으로 구분하여 한 번에 선언 가능합니다.

❌ try-catch (문제점)

  • finally에서 close() 직접 호출
  • close()도 예외 발생 가능 → 중첩 try
  • 코드가 길고 복잡

✅ try-with-resources

  • 블록 종료 시 자동 close()
  • finally 블록 불필요
  • 코드가 간결하고 안전

프로그래밍 연습문제
Q1개념 확인
다음 중 스트림(Stream)에 대한 설명으로 옳지 않은 것은?
① 입력 스트림과 출력 스트림은 데이터 흐름 방향이 반대이다.
② 문자 스트림은 2바이트(유니코드) 단위로 데이터를 처리한다.
③ 하나의 스트림으로 입력과 출력을 동시에 처리할 수 있다.
④ 사용 후 close()를 호출하여 자원을 반환해야 한다.
✅ 정답: ③
스트림은 단방향입니다. 하나의 스트림은 입력 또는 출력 중 하나만 담당합니다.
입력과 출력 모두 필요하다면 각각의 스트림을 따로 생성해야 합니다.
Q2출력값 예측
파일 "test.txt"에 "ABC"가 저장되어 있을 때, 다음 코드의 출력 결과는?
FileReader fin = new FileReader("test.txt"); int ch; while ((ch = fin.read()) != -1) { System.out.print((char) ch); } fin.close();
① 65 66 67 (ASCII 코드값)
② ABC
③ A B C (공백 포함)
④ 오류 발생
✅ 정답: ②
read()는 int를 반환하지만 (char) ch로 형변환하여 문자로 출력합니다.
형변환 없이 System.out.print(ch)를 쓰면 65, 66, 67이 출력됩니다.
Q3코드 완성
파일을 읽는 코드의 빈칸 ❶~❸에 들어갈 알맞은 코드를 고르시오.
try (FileReader fin = new FileReader("menu.txt")) { int ch; while ((ch = fin.❶()) != ❷) { System.out.print((❸) ch); } } catch (IOException e) { ... }
① ❶ write / ❷ 0 / ❸ String
② ❶ read / ❷ -1 / ❸ char
③ ❶ read / ❷ 0 / ❸ int
④ ❶ read / ❷ null / ❸ char
✅ 정답: ②
❶ read(): 파일에서 한 문자씩 읽는 메서드
❷ -1: read()는 파일 끝에 도달하면 -1 반환
❸ char: read()는 int를 반환하므로 char로 형변환해야 문자 출력
Q4코드 완성
기존 파일 "log.txt"에 내용을 이어서 추가하는 FileWriter 생성 코드로 올바른 것은?
① new FileWriter("log.txt")
② new FileWriter("log.txt", false)
③ new FileWriter("log.txt", true)
④ new FileWriter("log.txt", "append")
✅ 정답: ③
두 번째 매개변수 true가 append 모드입니다.
①과 ②는 기존 파일 내용을 삭제하고 덮어씁니다. (false가 기본값)
④는 두 번째 인자가 boolean이어야 하므로 컴파일 오류.
Q5오류 찾기
다음 코드에서 문제가 있는 부분과 그 이유를 고르시오.
try (FileReader fin = new FileReader("menu.txt")) { int ch; while ((ch = fin.read()) != 0) { // ← 여기 System.out.print((char) ch); } }
① try-with-resources를 사용했으므로 close()가 호출되지 않는다
② 파일 끝 조건이 0이 아닌 -1이어야 한다
③ (char) ch 형변환이 잘못됐다
④ catch 블록이 없으므로 컴파일 오류
✅ 정답: ②
read()는 파일 끝에 도달하면 -1을 반환합니다. 0이 아닌 -1과 비교해야 합니다.
0과 비교하면 파일에 null 문자(0번 코드)가 있을 때 잘못 종료되거나, -1을 만나지 못해 무한 루프가 될 수 있습니다.
try-with-resources는 자동 close()가 맞으며, catch 없이 throws 처리도 가능합니다.
Q6개념 확인
try-with-resources에 대한 설명으로 옳은 것은?
① try 블록 안에서만 close()를 직접 호출해야 한다
② 예외 발생 시에는 자동 close()가 실행되지 않는다
③ try() 괄호 안에 선언한 자원은 블록 종료 시 자동으로 close()된다
④ Java 11부터 지원되는 기능이다
✅ 정답: ③
try-with-resources는 Java 7부터 지원됩니다.
블록이 정상 종료되든 예외가 발생하든 관계없이 자원을 자동으로 close()합니다.
①: 직접 close() 불필요. ②: 예외 시에도 close() 실행. ④: Java 7+.

Q8단답형
파일을 읽을 때 파일 끝에 도달하면 read() 메서드가 반환하는 값은?
✅ 정답: -1
read()는 스트림의 끝(End Of File)에 도달하면 -1을 반환합니다.
이를 이용해 while ((ch = fin.read()) != -1) 패턴으로 파일 전체를 읽습니다.

Q10코드 작성 — 종합
"input.txt" 파일을 읽어 "output.txt"에 그대로 복사하는 코드를 완성하시오.
try-with-resources로 두 스트림을 동시에 선언하고 IOException 처리
try (FileReader fin = new FileReader("input.txt"); FileWriter fout = new FileWriter("output.txt")) { int ch; while ((ch = ___①___) != ___②___) { ___③___; } System.out.println("파일 복사 완료!"); } catch (IOException e) { ... }
① ❶ fout.read() / ❷ 0 / ❸ fin.write(ch)
② ❶ fin.read() / ❷ -1 / ❸ fout.write(ch)
③ ❶ fin.read() / ❷ -1 / ❸ fin.write(ch)
④ ❶ fout.write() / ❷ null / ❸ fin.read(ch)
✅ 정답: ②
❶ fin.read(): 입력 스트림(fin)에서 읽기
❷ -1: 파일 끝 도달 조건
❸ fout.write(ch): 출력 스트림(fout)에 쓰기
try-with-resources에서 두 스트림을 세미콜론(;)으로 구분하여 선언하면 둘 다 자동 close() 됩니다.

Q12코드 작성 — 종합
다음 중 char 배열을 이용한 파일 읽기 코드에서 빈칸 ❶, ❷에 들어갈 내용을 고르시오.
try (FileReader fin = new FileReader("menu.txt")) { char[] cbuf = new char[10]; int count; while ((count = fin.read(❶)) != -1) { for (int i = 0; i < ❷; i++) { System.out.print(cbuf[i]); } } }
① ❶ ch / ❷ cbuf.length
② ❶ cbuf / ❷ count
③ ❶ count / ❷ cbuf.length
④ ❶ cbuf / ❷ cbuf.length
✅ 정답: ②
❶ cbuf: read(char[])에 char 배열을 전달해야 함
❷ count: 실제로 읽은 문자 수. 파일 마지막에선 배열이 덜 채워질 수 있으므로 cbuf.length가 아닌 count만큼만 출력해야 올바릅니다.
