제네릭 (Generics) 타입 안전성

1. 제네릭이 필요한 이유

Object 배열로 다양한 타입을 저장하면, 꺼낼 때 강제 형변환이 필요하고 실수하면 ClassCastException이 발생합니다. 제네릭을 사용하면 컴파일 시점에 타입을 체크하여 이런 오류를 방지합니다.

❌ 제네릭 없이 (Object 배열)

Object[] array = new Object[2]; array[0] = "Hello"; // String array[1] = 100; // Integer (오토박싱) String s0 = (String) array[0]; // OK String s1 = (String) array[1]; // 런타임 오류! // ClassCastException 발생

✅ 제네릭 사용 (ArrayList<String>)

ArrayList<String> list = new ArrayList<String>(); list.add("Hello"); list.add(100); // 컴파일 오류! // 실수를 미리 감지 String s0 = list.get(0); // 형변환 불필요
핵심: 제네릭은 "이 컬렉션/클래스는 이 타입만 담는다"고 컴파일러에게 알려주어, 잘못된 타입 사용을 런타임이 아닌 컴파일 시점에 잡아냅니다.

2. 제네릭 클래스 선언 시험 필수

// 제네릭 클래스 Box<T> 선언 class Box<T> { private T item; // T 타입의 필드 public Box(T item) { // T 타입의 생성자 this.item = item; } public T getItem() { // T 타입 반환 메서드(getter) return this.item; } public void setItem(T item) { // T 타입 매개변수 메서드(setter) this.item = item; } }
T는 타입 파라미터(Type Parameter). 클래스를 선언할 때는 구체적 타입 대신 T를 쓰고, 객체를 생성할 때 실제 타입을 지정합니다.

3. 타입 파라미터 명명 관례

TType (일반 타입)
EElement (컬렉션 원소)
KKey (Map의 키)
VValue (Map의 값)
NNumber (숫자 타입)

4. 제네릭 클래스 객체 생성 시험 필수

// 타입 명시 방식 Box<String> b1 = new Box<String>("Hello"); Box<Integer> b2 = new Box<Integer>(100); Box<Donut> b3 = new Box<Donut>(new Donut("초코")); // 다이아몬드 연산자 <> — Java 7부터 타입 생략 가능 Box<String> b4 = new Box<>("Hello"); Box<Integer> b5 = new Box<>(100); // ❌ 기본 자료형은 사용 불가 → Wrapper 클래스 사용 Box<int> err = new Box<>(5); // 컴파일 오류! Box<Integer> ok = new Box<>(5); // OK (오토박싱)
⚠️ 제네릭에는 기본형(int, double 등) 사용 불가! 반드시 Wrapper 클래스(Integer, Double...)를 사용해야 합니다.

5. 제네릭 클래스 사용 예제

// Box<Donut> 사용 예제 Donut myDonut = new Donut("초코맛 도넛"); Box<Donut> myBox = new Box<>(myDonut); Donut d1 = myBox.getItem(); System.out.println("상자에서 꺼낸 도넛: " + d1.getName()); // 오토박싱과 제네릭 — Integer Box<Integer> b4 = new Box<>(); b4.setItem(4); // 오토박싱: int(4) → Integer(4) int i = b4.getItem(); // 언박싱: Integer(4) → int(4)

컬렉션 프레임워크 java.util

1. 컬렉션 프레임워크 구조

컬렉션 프레임워크는 여러 데이터를 표준화된 방식으로 저장하고 처리하는 클래스/인터페이스 모음입니다. 최상위 인터페이스 Collection 하위에 List, Set이 있고, 별도로 Map이 있습니다.

📋 List

순서 있음 · 중복 허용

  • ArrayList 주로 사용
  • Vector
  • LinkedList

🎯 Set

순서 없음 · 중복 불허

  • HashSet 주로 사용
  • TreeSet
  • LinkedHashSet

🗺 Map

키-값 쌍 · 키 중복 불허

  • HashMap 주로 사용
  • Hashtable
  • TreeMap
  • LinkedHashMap

2. 컬렉션 주요 메서드

메서드설명비고
add(element)요소 추가List: 순서대로 / Set: 중복 무시
remove(element)요소 삭제삭제 성공 시 true 반환
size()요소 개수 반환

3. ArrayList 사용 예제 시험 필수

import java.util.ArrayList; // 제네릭 적용 ArrayList 선언 ArrayList<String> list = new ArrayList<String>(); list.add("Hello"); // 추가 list.add(100); // 컴파일 오류! (String만 가능) String s0 = list.get(0); // "Hello" (형변환 불필요) System.out.println(s0); // Hello // 형 변환 오류 없이 안전하게 값 꺼내기 ArrayList<Integer> nums = new ArrayList<>(); nums.add(10); nums.add(20); nums.add(30); System.out.println(nums.size()); // 3 System.out.println(nums.get(1)); // 20 System.out.println(nums.contains(20)); // true nums.remove(Integer.valueOf(10)); // 10 삭제
💡 List vs 배열: 배열은 크기가 고정, List는 동적으로 늘어남. List는 add/remove로 자유롭게 요소 추가·삭제 가능. 크기를 미리 정할 필요 없음.
λ
람다 표현식 (Lambda Expression) Java 8+

1. 익명 클래스(Anonymous Class)의 이해

이름 없는 클래스. 인터페이스를 즉석에서 구현할 때 사용합니다. 일회성 구현에 유용하지만 코드가 길고 복잡합니다.

// 함수형 인터페이스 interface Makeable { void makeDonut(String donutType); } // 익명 클래스로 구현 — 코드가 길다 Makeable donutMaker = new Makeable() { @Override public void makeDonut(String donutType) { System.out.println(donutType + " 도넛을 만들고 있습니다."); } }; donutMaker.makeDonut("초코");

2. 람다 표현식으로 변환 시험 필수

익명 클래스에서 핵심만 남긴 것이 람다 표현식입니다. 불필요한 코드를 제거하고 ->로 연결합니다.

(String donutType)
→
{ System.out.println(donutType + " 도넛!"); }
// 익명 클래스 → 람다 표현식 변환 // 기본 형태 Makeable m1 = (donutType) -> { System.out.println(donutType + " 도넛을 만들고 있습니다."); }; // 코드가 한 줄이면 {} 생략 가능 Makeable m2 = (donutType) -> System.out.println(donutType + " 도넛을 만들고 있습니다."); // 매개변수가 2개: 쉼표로 구분 Sellable s = (donutType, price) -> System.out.println(donutType + " 도넛 가격: " + price + "원"); // return이 있는 경우 Discountable d1 = (price) -> { int discountPrice = (int)(price * 0.9); return discountPrice; }; // 표현식 한 줄 return → {} 와 return 생략 가능 Discountable d2 = (price) -> (int)(price * 0.9);

3. 람다 표현식 형식 정리 시험 필수

상황형식예시
매개변수 없음() -> { 코드 }() -> System.out.println("실행")
매개변수 1개(x) -> { 코드 }(name) -> System.out.println(name)
매개변수 2개(x, y) -> { 코드 }(a, b) -> System.out.println(a + b)
코드 한 줄() -> 표현식() -> "Hello"
return 한 줄(x) -> 반환값(price) -> price * 0.9

4. 함수형 인터페이스 (Functional Interface)

람다 표현식은 추상 메서드가 딱 하나인 인터페이스(함수형 인터페이스)에만 사용할 수 있습니다.

// 함수형 인터페이스 선언 interface Makeable { void makeDonut(String donutType); // 추상 메서드 딱 1개 } // 람다로 구현 Makeable donutMaker = (donutType) -> System.out.println(donutType + " 도넛을 만들고 있습니다."); donutMaker.makeDonut("초코"); // 초코 도넛을 만들고 있습니다.
핵심: 람다 표현식 = 익명 클래스의 간결한 표현. 함수형 인터페이스의 추상 메서드 구현 코드만 (매개변수) -> { 코드 } 형태로 작성합니다. 메서드 이름, @Override, 클래스 선언 등은 모두 생략합니다.

프로그래밍 연습문제
Q1출력값 예측
다음 코드의 출력 결과는?
ArrayList<String> list = new ArrayList<>(); list.add("초코"); list.add("레몬"); list.add("딸기"); System.out.println(list.size()); System.out.println(list.get(1)); System.out.println(list.contains("레몬"));
① 2 / 레몬 / true
② 3 / 레몬 / true
③ 3 / 딸기 / false
④ 3 / 초코 / true
✅ 정답: ②
add() 3번 → size = 3
get(1) → 인덱스 1 = "레몬"
contains("레몬") → 포함되어 있으므로 true
Q2코드 완성
다음 제네릭 클래스 Box<T>의 빈칸 ❶~❸에 알맞은 코드를 고르시오.
class Box<❶> { private ❷ item; public ❸ getItem() { return item; } }
① ❶ Object / ❷ Object / ❸ Object
② ❶ T / ❷ T / ❸ T
③ ❶ T / ❷ Object / ❸ T
④ ❶ Type / ❷ Type / ❸ Type
✅ 정답: ②
제네릭 클래스 선언 시 클래스명 뒤에 <T>를 붙이고, 타입이 필요한 모든 곳에 T를 사용합니다.
❶ T (타입 파라미터 선언) / ❷ T (필드 타입) / ❸ T (반환 타입)
Q3오류 찾기
다음 코드에서 컴파일 오류가 발생하는 줄을 고르시오.
01 Box<String> b1 = new Box<>("Hello"); 02 Box<Integer> b2 = new Box<>(100); 03 Box<int> b3 = new Box<>(5); 04 Box<Donut> b4 = new Box<>(new Donut("초코"));
① 1번 줄 — new Box<>에 타입을 명시해야 한다
② 2번 줄 — int 값은 Integer에 넣을 수 없다
③ 3번 줄 — 제네릭에 기본형 타입은 사용할 수 없다
④ 4번 줄 — 사용자 정의 클래스는 제네릭에 사용할 수 없다
✅ 정답: ③
3번 줄: 제네릭 타입 파라미터에는 기본형(int, double 등)을 사용할 수 없습니다.
반드시 Wrapper 클래스 Box<Integer>를 사용해야 합니다.
1, 2, 4번은 모두 정상 코드입니다. (2번: 오토박싱으로 int → Integer 자동 변환)
Q4출력값 예측
다음 코드의 출력 결과는?
Box<String> b1 = new Box<>(); b1.setItem("도넛"); System.out.println(b1.getItem()); Box<Integer> b2 = new Box<>(); b2.setItem(42); int val = b2.getItem(); System.out.println(val * 2);
① null / 84
② 도넛 / 84
③ 도넛 / 42
④ 오류 발생
✅ 정답: ②
b1.setItem("도넛") → b1.getItem() = "도넛"
b2.setItem(42) → 오토박싱으로 Integer(42) 저장
b2.getItem() → 언박싱으로 int 42 반환 → 42 × 2 = 84
Q5코드 변환
다음 익명 클래스 코드를 람다 표현식으로 올바르게 변환한 것은?
// 익명 클래스 Makeable maker = new Makeable() { @Override public void makeDonut(String donutType) { System.out.println(donutType + " 도넛!"); } };
① Makeable maker = donutType { System.out.println(donutType + " 도넛!"); };
② Makeable maker = (donutType) -> System.out.println(donutType + " 도넛!");
③ Makeable maker = () -> System.out.println("도넛!");
④ Makeable maker = new Lambda(donutType -> System.out.println(donutType));
✅ 정답: ②
람다 형식: (매개변수) -> 코드
- makeDonut의 매개변수 donutType을 (donutType)으로 작성
- 코드가 한 줄이므로 { } 생략 가능
①: 화살표(->) 없음. ③: 매개변수 누락. ④: 잘못된 형식.
Q6코드 완성
다음 람다 표현식의 빈칸 ❶, ❷에 들어갈 코드를 고르시오.
// 두 정수를 받아 합을 반환하는 람다 Calculator calc = ❶ -> ❷; System.out.println(calc.add(3, 5)); // 8 출력 기대 // Calculator 인터페이스 interface Calculator { int add(int a, int b); }
① ❶ () / ❷ a + b
② ❶ (a) / ❷ a + b
③ ❶ (a, b) / ❷ a + b
④ ❶ (a, b) / ❷ return a + b
✅ 정답: ③
add(int a, int b)는 매개변수가 2개 → ❶ (a, b)
반환값이 표현식 한 줄이면 return 생략 → ❷ a + b
④는 return을 쓰면 반드시 { }도 함께 써야 합니다: (a, b) -> { return a + b; }
Q7컬렉션 구분
다음 요구사항에 가장 적합한 컬렉션 타입은?
"학생 이름 목록을 저장하되, 같은 이름이 중복 저장되면 안 됩니다."
① ArrayList<String> — 순서 있고 중복 허용
② HashSet<String> — 순서 없고 중복 불허
③ HashMap<String, String> — 키-값 쌍 저장
④ Object[] — 기본 배열 사용
✅ 정답: ②

Q10코드 완성 — 종합
다음 코드의 빈칸을 채워 "초코 도넛을 만들고 있습니다."가 출력되도록 하시오.
interface Makeable { void makeDonut(String donutType); } Makeable maker = ___①___; maker.makeDonut("초코");
① () -> System.out.println("초코 도넛을 만들고 있습니다.")
② (donutType) -> System.out.println(donutType + " 도넛을 만들고 있습니다.")
③ new Makeable("초코")
④ (donutType) -> { makeDonut(donutType); }
✅ 정답: ②
makeDonut(String donutType)에는 매개변수가 1개 → (donutType)
maker.makeDonut("초코") 호출 시 donutType = "초코"
→ "초코" + " 도넛을 만들고 있습니다." 출력
①: 매개변수 없이 하드코딩 → "초코"가 아닌 다른 값 넘겨도 항상 같은 출력.
